# 0.2.x 实施进度

0.2.1 已完成 L12 单文件字符 Transformer。五个接口分别检查下一字符目标、嵌入、注意力、残差块与输出头，完整提交进入 CPU 梯度检查、训练和采样。L04 的 MLP 练习仍可独立使用。[版本验证记录](VALIDATION.md)

## 0.2.0 的设计契约

L04-train 已接入工作台。运行器采用固定八步 SGD，完整实现及门禁见同目录 DEVELOPMENT_STATUS.md 和 VALIDATION.md。以下为本阶段的设计契约。

入口选 L04，保留已有 configure() 引导实验，另设 train-mlp-v1 活动。学习者先预测漏掉 zero_grad 或调大学习率的影响，在一个 submission.py 中实现 train_step(model, optimizer, batch) 和 validate(model, batch)。训练步骤依次清梯度、前向、计算 MSE、反传及更新；验证在 eval/no_grad 下使用独立样本。提交前记录预测，运行后单独提交解释，再生成到期复习。

## 数据与执行契约

复用 RunRecord、attemptId、runId、版本、不可变镜像与无网学生进程。快照增加训练协议版本、数据生成器版本、划分索引摘要、初始参数摘要及固定种子。CPU 单线程、单文件、步数上限 200，沿用容器内存、时限与输出上限。训练代码仅在 UID 65534 子进程内执行。引导实验的控制器继续使用现有 configure 接口。

训练数据按固定样本 ID 切分，验证数据由控制器在训练后单独提供。可信控制器只接受形状受限的数值数组与状态字典的纯数据表示，拒绝 pickle。学习者日志和自报 loss 标为 student；可信控制器对返回的参数在独立样本上重算预测与误差，产生 program 检查。优化器状态、梯度及前后参数在有限的小批次上传输，控制器用独立初始值重算首步梯度、更新方向和幅度，再测试连续两步和验证前后参数一致性。

## 第一条路径的验收

固定种子参考解应复现训练/验证曲线。省略 backward、漏 step、未清梯度、使用训练集计算验证误差、验证期间更新参数以及硬编码指标的错误解应分别失败。验证集样本 ID 与训练集不相交。学习记录能从解释、复习和检查返回同一快照，学习者报告和导师评论保留各自来源。

## 已在 0.2.1 实施的扩展顺序

完成 MLP 的预测、运行、解释、复习全流程后，将现有 NumPy solve 题的数值输出作为对照，逐件重写为保留参数和 autograd 图的 PyTorch 模块。依次接 Embedding、因果 Attention、多头投影、Pre-LN、FFN、输出头与 shifted targets。每步验证小批次前向和梯度、因果未来不变性及 batch 隔离，最后才组装微型语言模型。

## M1 · 0.3.0 从单文件组装走向可复用组件 · L

**依赖**：0A–0C 的数据与尝试身份、0F 的可复现候选包。沿用 L04/L12 的有界 JSON、CPU 进程隔离、独立数值预言机及数据摘要。

1. 在 catalog 和类型中建立组件合同与依赖顺序。把现有 shifted、embed、attention、block、logits 映射为项目步骤；细分位置表示、mask、多头拼接、Pre-LN/残差、FFN、LM head 和 shifted loss。NumPy 概念练习与 PyTorch 可求导组件分开标记。
2. 新增项目提交快照，列出各组件的源码、版本和哈希；runner 按快照在学生进程内组装。控制器侧参考模块仅用于校验。保留原有单文件练习和历史运行的重放入口。
3. 增加两组以上合法形状，含不同 B/T 和 head 数；用独立输出、输入及参数梯度、未来扰动、批次隔离、训练／验证无交叠检查。学生能从失败项定位到具体组件。
4. **完成条件**：替换一个组件会改变项目输出或导致明确失败；错误 mask、硬编码两头、错误 shift、错残差、detach、遗漏更新被定向拒绝。正确组件在真实 CPU 完成前反向、训练和采样；同种子复跑一致，旧项目继续可读。范围限定单机小模型，GPU、远程执行和任意 Notebook kernel 延后。

## M2 · 0.4.0 运行诊断与可视化 · M–L

**依赖**：M0 的快照身份；M1 提供组件、层与头的稳定名称。先冻结事件格式，再做图表。复用已有双 run 的真实 loss 叠加。

- runtime 发出限量的 shape、梯度范数、参数增量和各层／头的 attention；记录采样方式、原始形状、来源和精度。Host 对事件数、总字节、矩阵及导出大小设上限，先校验再持久化。SQLite 保存小索引，较大产物按 run 查读。
- 接口按 runId、源码哈希、seed、环境、协议及 artifactId 检索。旧运行没有诊断项时界面显示缺失；示意图明确标识。对照视图列出改变的变量，支持离群值色阶、行列索引、数值表和多处修改的行级 diff。
- **完成条件**：从热图单元格可回查具体 run／层／头／行列和原值；切题、改参数、失败后重试、两 run 交替查看均无串图。超限张量被采样或拒绝，色阶截断可见。键盘可从结果／导师回到编辑器；宽窄屏均可访问运行控制和原始数据。范围限定诊断与对照，长训练续跑另立协议。

## M3 · 0.5.0 项目式学习与复现 · L

**依赖**：M1 的组件提交与 M2 的诊断产物，先完成一个项目切片再增加模型种类。

- 先把字符项目串成预测→提交→运行→解释→变式→到期复习，保存预测／解释草稿、对应 runId、实际帮助和独立作答。导师引用明确步骤或产物，学习者自述与程序通过分别显示。
- 增加合成时序／结构振动项目。按连续时间段或原信号组切分，再开窗口；归一化只拟合训练段。MLP、1D CNN 和简化 Attention 共享生成器、分割和训练预算，允许学习者解释结果及混杂因素。
- 在现有数据导出上增加项目清单，包含源码、组件哈希、seed、版本、环境／数据摘要、运行结果和解释。导入到空临时 profile 后可复核，不执行未确认的外来代码。
- **完成条件**：换到新 profile 复现指定 run，确定性输出一致或满足预先规定的数值容差；泄漏未来信息或跨分割窗口的坏实现失败；推迟复习后到期时间真实变化，完成后只移除对应项目／run。课程市场、自动生成整门课程和资源调度延后。

**首个实施交付**：提交 R1、R2、R3 的临时 profile 复现测试及一份旧共享库归属方案。先用真实旧库夹具演练中断与恢复，再开始改默认路径。由此可以独立验收数据安全，并给后续的组件和诊断开发一个稳定起点。

## 四个版本共同通过的检查

- **构建和渲染。** 严格 TypeScript 检查、Host 和 Client 构建、运行时包入口和构建输入哈希校验均通过。浏览器工厂仅允许加载 `react`、`react/jsx-runtime`、`react-dom`。源码检查覆盖危险 HTML 插入和动态求值。中英文逐课 SSR 将输入的 HTML 标签渲染为文本。P5 另在 DOM 中实际操作五个新增探索器，从调整控件、解锁提交到 Host 复算并保存证据，整条路径通过。

## 各阶段的判定依据

| 阶段 | 实际核对的行为 |
| --- | --- |
| B · GPU 访存 | 分别核对对齐、偏移、跨步、同地址广播及各 Bank 的通道。用 `35 × 50` 和 `1 × 3` 验证二维网格边界。分块乘法的输出与独立 NumPy 对照一致，逐项核对 HBM/SRAM 的读写元素数和字节数，16 边长分块的 HBM 读取量恰为朴素实现的 1/16。最终累计门禁额外跑了漏边界保护和数值正确但流量超标两个反例。 |
| C · 训练 | 复算混合精度下的 16P/18P 静态字节和重算激活后的显存与 FLOPs。容器实际执行参数更新、溢出后的动态缩放、三个在线 Softmax/Attention 微步骤。数值对照与中间张量大小分别判定，通过稠密 Attention 的负例确认完整分数矩阵会触发失败。导师请求只携带选中且属于当前练习的运行事件，概念提示测试检查了参考解隔离。 |
| D · 分布式 | 在四个独立 Gloo 进程上用点对点原语完成环形集合通信，对照 PyTorch 集合通信与独立数值结果。另检验梯度分桶与计算重叠、两步带动量的 ZeRO-1 分片更新，以及列并行加行并行 MLP 的一次规约。覆盖 2、3、4 个 rank 的启动路径。流水线逐格验证数据依赖、空闲时间及激活峰值，4 级、12 个微批时气泡为 20%，第一级峰值由 GPipe 的 12 份降至 1F1B 的 4 份。 |
| E、X · 服务与容量 | 对三个序列长度 12、48、96 的增量 KV 解码逐位置核对因果 Attention，记录与前缀重算各三次的 CPU 耗时中位数。16-token 分页覆盖跨页、部分前缀共享、写时复制、引用计数、耗尽回滚和释放复用。INT4 校验实际双半字节打包、负值、全零组、尾组和分组误差。调度器核对排队对首 token 延迟的影响、每 token 间隔、吞吐和 KV 页数。容量台分别提交 70B 推理与 13B 训练方案，并验证显存、拓扑、精度、并发、延迟、链路六项条件。开放设计说明的判定保留为 `inconclusive`。 |

**Ring 公式口径。** 在忽略本地归约算术开销的通信模型中，每个 rank 在两个阶段各经历 `N−1` 轮，每轮消息为 `M/N` 字节。界面同时显示总耗时 `2(N−1)(α + M/(Nβ))` 和路线图指定的按进程数归一化值 `总耗时/N`。四进程、4,000 字节、启动延迟 5 µs、链路 1 GB/s 的回归结果分别是 36 µs 和 9 µs。[Thakur、Rabenseifner 与 Gropp，集合通信时间模型](https://fs.hlrs.de/projects/rabenseifner/publ/HPCA_collectives.pdf)

## 分布式生命周期与归档

- **进程与输出。** 在独立的降权会话中由 `spawn` 创建 worker，绑定回环地址、随机端口和 `lo`。分布式专测让 rank 0 跳过一次规约，25 秒后收到双语诊断与每个 rank 最后所处原语。四个 rank 的同时输出触发字节上限。在另一次实验中，先从 Docker 观察到四个 worker，再卸载 Cordis 插件并核对容器已移除。
- **PID 配额。** 在确认 `pids.max=256` 的临时容器中，由单一生产者至多尝试创建 256 个短时线程，读取内核 `pids.events.max` 确认至少一次被拒，随后回收。这项测试覆盖实际 cgroup PID 配额与清理。无限递归 fork 负载未执行。
- **数据库。** P2 起，每版用冻结的 v0.1.0 SQL 结构和序列化数据连续打开两次，检验草稿、笔记修订、运行、证据、阅读/跳过状态和复习队列。P5 另外从 Git 提取 v0.1.0–v0.4.0 的源码，由 v0.1.0 实际创建临时库并写入一次 Docker 运行。五版依次打开同一个 `ai-infra-lab.sqlite`，逐行比对 `kv`、`drafts`、`runs`、`history`。各版均验证 `application_id=1229734210`，保留原始运行版本和修订号。
- **导入。** 覆盖有效 v0.1.0 归档恢复和 P5 归档往返、重复导入幂等、答题与运行关联、证据与练习绑定、事件序号与状态一致性。拒绝超过 4,000,000 个 UTF-8 字节、1,000 条运行或 5,000 条证据的输入，也拒绝冲突 ID、错绑事件、非法时间线、代码哈希不符及畸形结构。每个失败批次均复查先前数据，确认事务未留下部分写入。

## 验收范围

执行环境为单机 CPU Docker 和回环 Gloo。CPU 耗时曲线反映这台机器上的采样，GPU 带宽、峰值算力与网络延迟来自课程模型。容量结果基于界面列出的硬件及工作负载假设。跨节点通信、CUDA/NCCL、真实 70B/13B 部署均未实测。Attention 中间张量上限覆盖测试样本的 eager ATen 路径。亮暗主题使用宿主主题色，界面通过中英文 SSR 与 DOM 操作验收，未进行桌面逐像素截图比较或在线大模型导师会话。

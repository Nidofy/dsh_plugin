## 实际内容

本地版本 **0.7.0-preview.2**，增加受控桌面模式和可完整游玩的三连棋。它复用批准餐桌身体和原左右两席；棋盘是明确标注开发预览的原创代码矢量，没有新增正式家具原画，没有把该预览当成M5全部家具或0.8完成。

- 布置→家具：棋局桌面/用餐桌面只是选择草稿，必须“确认桌面用途”才通过同一CAS保存；取消不写。主活动、实际占用餐桌、拍照或装修时不能切换用途。
- 心愿→全部心愿→开发预览：两位在场居民实际寻路到原餐桌两席，停留观察后才能落子。席位被外人占用或路径阻塞时拒绝开始，不瞬移让路。
- 玩家执○、朋友执×，九格面板有键盘输入，也能在世界棋盘点击。居民先尝试连线、再阻止连线、最后按稳定居民ID选择角落；不读系统时间、不调用模型、不消费世界RNG。
- 一次玩家落子和至多一次居民回应生成一份候选，一次CAS确认后同时可见。每轮之后停留观察两秒；终局单独进入收尾观察，明确“记下这一局”才写原有手账和共同经历。
- 取消、离场或有效拖走参与者不留未完成记忆。输赢不扣物品。首次完成解锁“同桌棋子”，沿用原挂点/照片/附近观察消费者；重复完成保留首次事实，只加次数。
- 原三小游戏派生心愿仍按原三个计算，不因新增预览倒退；原19类手账增加一类，变为20类，收藏仍同一数据结构。

## 同一场景几何

物件身份 `game-table` 是eat组桌面变体，不是第二件并列家具。既有桌体默认rect=(123,330,204,68)，两席(175,374)/(273,374)，原障碍与两种合法锚点全部保留。替代锚点整体x−54。

`table-geometry.ts`集中定义棋盘rect=(189,332,72,24)与九格中心/命中；替代锚点rect=(135,332,72,24)。渲染和父/子frame输入均从这份几何计算。棋盘在桌前层3980之上、活动手层3990之下，depth=3985；game模式隐藏原饭碗。照片渲染同一worldContent。不会增加障碍或改变可走区域，也未把视觉棋格当可站立点。

新增`TableArt`为一个Container/Graphics，按位置与棋子状态缓存重绘，复用现有帧循环；不增加PNG、纹理或永久计时器。角色复用已批准纸娃娃的观察/等待动作，本轮没有新“手指准确抓棋子”的原画或动捕，不把它写成正式新动作资产完成。

收尾复核发现，桌面用途只是新展示偏好，旧自主用餐/茶会仍会发生；原候选会同时显示棋盘和持碗手臂/茶杯。最小修复为用餐预约、用餐动作、茶会和其他以eat为目标的故事期间暂收棋盘，空闲再显示；同一纯判断驱动棋盘、餐桌道具和场景指标。只隐藏eat道具，不影响其他家具。没有禁用日程、改变rules4/RNG或写入额外存档；UI明确说明自动暂收语义。修复前候选B（1ca036b4…593544）及其浏览器证据保留，不能作为最终修复包的直接运行证据。

最终构建Host逻辑块144.15kB、client532.89kB、frame675.37kB；相对preview.1的124.57/500.31/654.71kB，增长主要来自被冻结的7格式解码及新棋局逻辑/UI。归档32,165,883 bytes，较preview.1增加11,746 bytes，仍276文件。没有增加纹理或放宽已有资源上限；实际软件帧率/隐藏成本另由独立QA采样。

## 数据与协议

当前 **world8 / scene3 / rules4 / content5 / preferences3 / frame6**。规则4的普通生活选择不改；新的手动活动有独立稳定定义。`living-state-v7.ts`与`play-catalog-v4.ts`保留上轮闭合格式与目录，1–7先经旧解码器验证再升级；7仍拒绝8和新字段。

新字段`play.tableMode`只允许dining/game，旧存档默认dining；新纪念物固定ID `table-stones`默认null。只有`table-game`使用9格board（-1空、0玩家、1居民）与最多9步choices（字符串0–8）。验证器完整重演最多5轮确定性回应，拒绝重复格、伪造棋子、错误回应、胜负之后继续落子和错误阶段。终局只允许stage1；其他七项保持原字段界限。

棋局操作令牌为UUID:stage:choices.length，旧7项仍为UUID:stage。frame6增加闭合`table-move`意图，含cell/point/token；子frame在按下与抬起时核对同格、同轮，父runtime重新计算命中。仍沿用token/source/origin/sequence/viewport门禁，入口first-frame语义不变。未知ACK只读核对，不重放玩家/居民回应。

所有状态、回忆、摆放仍由同一个SaveStore/租约/CAS写入，48KiB世界和64KiB封装上限不变。原7快照在升级写入后保护原字节，42次新保存后仍保留。0.7.0-preview.1不能读8；降级需停止新插件，在另一隔离profile使用受保护的旧快照，不能删除新字段强行回退。

## 2. 产品决定与范围取舍

产品定位：**七位居民组成的离线轻生活小院，玩家通过互动、发现和布置，留下自己的故事。**

核心循环：发现小事 → 参与互动 → 留下手账并发现物件 → 布置小院 → 产生新的反应。

| 分歧 | 本方案决定 | 原因 |
| --- | --- | --- |
| 游戏内容与 Agent 仪表盘 | 游戏优先；宿主状态后续可选 | 没有 Agent 任务时也能完成玩法 |
| 三座七人争抢与增加容量 | 0.4 先餐桌双座；0.5 再增加双座长椅 | 当前阻路直接放弃，不能把掉头当成成熟社交 |
| 真实钟与模拟钟 | 可见模拟时间；隐藏停、不补算离线生活 | 延续当前产品语义，不制造上线压力 |
| 数值养成与轻参与 | 先偏好、共同经历、短反应 | 暂无必要加入饥饿/精力三条数值条和关系衰减 |
| 货币商店与发现奖励 | 一次性故事/装饰解锁 | 避免引入产出、价格、刷取、每日结算等额外系统 |
| 先铺基础框架与先做内容 | 只增加首条玩法需要的数据及迁移 | 不预埋货币、天气、访客等大量无消费者字段 |
| 独立 meta 与原子完成 | 完成、手账摘要、解锁同一世界提交 | 防止完成已保存、奖励丢失或重复 |
| 旧随机序列永久不变与规则演进 | 同规则版本保持确定性；规则升级可改变结果 | 旧档兼容不等于新旧版本行为永远逐 tick 相同 |

保持：当前 Q 版纸娃娃、柔和背景、七个角色 ID、离线资源、现有 Cordis 接入、单 owner、CAS、保守快照回收、Git 共存、Live2D 互斥和主聊天独立。

近期不纳入：第八角色、联网社区、持续 LLM 对话、抽卡、经济商店、强制日常、离线惩罚、任意资产导入、完整自由装修、复杂转身/拥抱、新原生窗口。照片在 0.5 独立交付，不拖延 0.4 核心闭环。

## 4. 0.4 的实际可玩内容

### 4.1 一条完整下午茶

1. 世界页显示一条可忽略的心愿，不弹出全局提示、不抢主聊天焦点。
2. 心愿页从在场居民中选择两位，再选择「白米饭」或「茶点」。免费，无库存和消耗。
3. 核验参与者、两席、活动冲突、两条路径。全满足才同时预留；失败不留下半个预留。
4. 两人分别走向座位。先到者等待另一位；两人都到达后才进入共同行为。
5. 播放 2–3 轮本地短句与表情。食物、角色不同会产生可读差异；保留回看文本。
6. 模拟确认事件完成，原子提交「首次同桌」见闻、心愿完成和风铃解锁。成功回执后显示获得提示。
7. 布置页提供三个合法风铃槽位；预览、撤销和确认是真实操作。
8. 摆放成功后，居民出现一次与风铃相关的反应。重复打开、重启仍保留手账、解锁和位置。

新档只有一人时，心愿给出「邀请另一位入住」入口，不暗中改成七人。七人全部可选；内容以角色反应模板和少量特殊配对组成，不要求首版写完 21 套专属故事。

建议首版内容预算：每人 6 条基础情境短句（42 条，均有中英文），再制作 3 个食物/配对分支、1 页首次同桌、1 件风铃和每人至少 1 条风铃反应。蓝鲸与 Claude 作为首个美术校准组合，其余角色沿用已批准姿态并逐一验证接触位置；这是最低制作清单，不是已完成数量。

### 4.2 事件状态与时序

状态链：`可开始 → 前往座位 → 同桌交流 → 待提交完成 → 已完成`。失败或主动中止回到可开始；已获得的收藏不会因为取消重玩而消失。

拟实现的事件状态只保存事实：事件定义 ID、实例序号、参与者、食物、阶段、座位引用、当前对话段、阶段剩余 ticks。动作时间和路线继续由角色意图表达；事件状态与意图由同一 reducer 修改，并进行交叉校验。

同时最多一个主要事件。优先级：显式取消/有效拖放 > 当前事件 > 普通自主活动。参与者不会在剧情中途被自主决策带走；其他居民正常生活。

| 情况 | 决策 |
| --- | --- |
| 座位已被第三人使用 | 提示等待或稍后开始；不强行抢占、不无限排队 |
| 参与者正在普通活动 | 接受邀请时统一释放其旧意图，切换到茶会；新预留失败则保持原活动 |
| 两人尚未到齐 | 先到者保留座位并等待，不独自完成剧情 |
| 路上被挡 | 事件内有限等待和重寻路；初值 3 次重试、最多 30 秒可见模拟时间，试玩后调节 |
| 仍不可达 | 取消整次事件，释放两席，显示原因；不产生奖励 |
| 点击参与者 | 可以选择/查看；一般问候排到当前台词之后，不覆盖剧情 |
| 拖动参与者 | 超过阈值后暂挂整个双人事件的时钟/参与者推进；其他人继续活动 |
| Esc 取消拖动或非法落点 | 恢复原事件，保留拖动事务语义；相关剩余时长/租用期限一起冻结 |
| 有效放下参与者 | 原子取消双人事件、释放双方事件预留，再应用新落点 |
| 移出参与者/切换为另一居民 | 说明将取消事件；确认后取消并释放，再移出/替换 |
| 用户暂停、sidebar、关闭、断连 | 暂停，不取消；恢复后继续已保存/内存中的相同阶段 |
| 插件重启 | 恢复最近成功快照；未保存的少量过程可能重演，不承诺保留已销毁内存 |
| 重复完成/回执丢失 | 同一事件实例只完成一次，首次解锁始终只发生一次 |

当前 step 只接受一个 held actor，事件拖拽需要扩展为参与者集合或等价的事件暂挂机制。不能只冻结被抓起的人，却让另一人用完活动或过期释放座位。

### 4.3 时间与重复游玩

0.4 采用固定时速，建议一个小院日对应 30 分钟可见模拟时间，从午后开始；24–36 分钟是可调平衡范围，先不开玩家时速设置。日历从固定 offset 与 ticks 派生，不需额外存储一套时钟。

未来支持时速时再新增连续累计时钟/epoch；不把全部旧 ticks 乘以新倍率。界面深浅主题与小院日夜分别设置，深色 UI 不自动代表小院夜晚。

首次茶会获得风铃；重玩可更换组合/食物、查看其他反应，但不重复发风铃、不无限增加手账行、不积累货币。没有每日刷新或过期。剧情长度以舒适读完为准，完整体验目标 3–8 分钟，不人为添加等待凑时长。

## 5. 技术结构与代码落点

## 6. 世界格式、场景迁移与一致提交

### 6.1 版本职责

| 版本 | 本次建议 | 何时变更 |
| --- | --- | --- |
| 包版本 | 0.4.0 开发目标 | 可交付功能与兼容说明变化 |
| world schema | 3 → 4 | 首次持久化事件、发现和风铃布局 |
| scene version | 1 → 2 | 双座几何/接触点定稿后升级 |
| simulation rules | 新显式版本 1，旧规则视为 legacy | 决策、事件与随机消费规则变化 |
| content revision | 构建目录 revision/哈希 | 静态内容变化；正在进行的事件保留对应定义版本 |
| frame protocol | 1 → 2 | render view、反馈、projection 契约变化 |

不在 0.4 泛化 worldId 和多场景结构；保留 `bluewhale-courtyard`。文案修正不应强制升级 schema；事件阶段被改写则必须迁移在途事件或继续识别旧定义。

### 6.2 schema 4 的最小持久状态

保留现有字段，包括 actor/companions，避免顺手重写整套多人模型。拟增加：

| 字段组 | 内容与边界 |
| --- | --- |
| `rulesVersion` / `contentRevision` | 当前兼容语义及目录身份 |
| `eventSerial` | 安全整数；确定性递增生成事件实例 ID，不把网络随机 UUID 注入模拟 |
| `activeEvent` | null 或一个茶会实例；两名合法且不同的在场成员，至多两个座位 |
| `progress` | 已完成心愿 ID、已解锁物件 ID、已发现组合/反应 ID；去重集合，有固定上限 |
| `journal` | 首次同桌等有界结构化事实：模板 ID、参与者、食物、tick、事件 ID；不保存全文/照片 |
| `decorations` | 风铃的稳定物件 ID、合法槽位 ID 或未摆放；layoutRevision |
| `feedbackState`（仅必要部分） | 会影响玩法去重/冷却的标记；纯视觉气泡队列不入档 |

状态不是通用 JSON 仓库：角色、物件、事件、模板、slot 全部白名单；不允许脚本、表达式求值、路径或任意 HTML。

建议首版上限：活跃事件 1、手账结构记录 32、解锁/发现各不超过 64 个 ID，ID/枚举均有长度限制。用 UTF-8 序列化测量容量，不按汉字字符数估算。

**容量门槛**：设计目标 world ≤48 KiB；save POST、Saved 文件及 state 响应各自计算完整封装，均须满足 64 KiB 边界并留余量。Host 请求/文件按字节限制，但当前 runtime 响应按字符串长度判断，实施时统一为有界字节读取。照片、大段文本和无限历史不得进入 world。

### 6.3 迁移必须覆盖整个保存路径

目前 `validateWorld` 同时承担旧档读取、canonicalization 和当前场景验证。直接把 scene.version 改成 2，会让旧存档在读取、save 对 current/previous 的检查、recover 和 prune 中失败。

实施顺序：

1. 保存 scene v1 的不可变最小几何定义和 schema 1/2/3 解码器，按存档自身版本验证，先证明旧数据合法。
2. 将合法旧状态在内存迁移至 schema 4/scene v2；不绕过原 hash、修订、owner 和路径检查。
3. 稳定 ID 映射旧 `eat/main` 到新桌位。几何未变的角色保留原位置；受影响的路径/意图重新计算，不能保留指向废弃座位的路线。
4. 失效活动受控取消。非法脚点按稳定角色顺序，在经过验证的安全点中重新安置，同时检查 24px 间距；不能把七人都放到一个 spawn。
5. 保留 ticks、rng、用户暂停和所选角色身份；只有新功能采用默认值。未知 schema/scene 拒读，不能当作新世界。
6. 第一次新保存仍通过当前 CAS 发布新快照。迁移前 current 指针与原快照建立受保护的升级备份引用，沿用/扩展现有保护引用机制。
7. prune 能识别历史合法快照；升级备份不因超过最近 32 份而被回收。无法识别者保守保留并诊断，不能靠禁用全部回收掩盖兼容错误。
8. previous 恢复、损坏 current 恢复、混合版本目录回收使用同一套历史读取规则；不能只让正常加载通过。

旧插件拒读格式 4。回退是关闭新插件后，显式使用受保护的升级前状态/副本；不承诺旧版能直接读已迁移 current。回退说明和验证随版本交付。

### 6.4 完成、奖励和 UI 提交回执

当前 `save(): void` 和吞入 error 状态的保存 Promise 不足以支撑「已获得」提示；`await flush()` 返回不等于某一条游戏命令明确提交成功。

拟新增具名命令结果：`pending → committed | rejected | unknown`。运行时记录命令 ID 与实际 save operationId 的关系，区分纯 UI 导航、可回滚草稿和需要持久化的关键动作。

关键动作（开始事件、完成事件、确认布置、取消并移出）串行处理：

1. 校验当前 owner/epoch/世界前置条件，等待已有保存完成。
2. 在候选状态中一次修改相关事实；事件完成与 journal/progress/unlock 一起变化。
3. 关键提交期间增加 `commit-pending` 暂停原因并禁止依赖奖励的后续写操作。UI 可以展示待确认，不提前宣布已保存。
4. 发一次带 expectedRevision/operationId 的 save。保存成功后发布 committed view 和一次获得反馈。
5. ACK 不明先查询 state，核验 profile、epoch、operationId、revision。确认已提交则恢复成功；无法确认则保留候选、暂停和 unknown，不能换一个 operationId 自动重发。
6. 事件实例完成标记和一次性 unlock 同快照去重；运输层 operationId 不替代游戏层去重。现有 SaveStore 只识别当前操作，不是无限操作历史表。

不新增独立 reward/meta writer。0.4 手账是权威快照的只读投影，不需要外部日志服务。0.5 相册才引入独立文件与幂等引用清理，避免把未来 outbox 框架提前塞入首版。

## 7. 双座家具、内容与渲染方案

### 7.1 双座不是复制一条 hotspot

当前 `placement()` 使用第一个命中的 hotspot；如果复制重叠 hit 区，只会命中第一席。当前 actor 脚点间距要求 ≥24，而视觉宽度约 108，满足碰撞不代表两个角色坐在一起不会重叠。

首版继续让热点用 `(furnitureId, seatId)` 标识，但明确区分家具渲染实例与座位热点：

- 同一桌子绘制一次，座位各有 anchor、接近点、局部命中区、道具位置和遮挡信息。
- 点击/拖放先得到候选席，过滤已占用/不可达席，再按指针距离和稳定 ID 决定；没有可用席明确拒绝，不悄悄吸附到别的家具。
- 事件开始同时检查并获取两席。任意一步失败，原事件/角色状态不变。
- `seatAvailable`、意图校验、人物脚点间距和视觉接触检查一起覆盖；两个角色不能共享一条不区分先后的狭窄抵达路线。
- 只对事件路径加入有限重试/错峰进入，不趁机重写完整人群导航。普通漫步算法保持现有行为，后续根据长时指标再优化。

双座场景先灰盒验证 1/2/7 人。若现有桌面放不下两个批准比例的角色，调整桌子位置/宽度和局部几何，并制作新桌面前后片；不把角色缩到难辨认，也不靠缩小碰撞半径掩盖穿插。

0.4 活动位从 3 增至 4；0.5 才尝试书桌 1、餐桌 2、坐垫 1、长椅 2，共约 6 席。六类目录不等于六件大家具必须同时塞入当前场景。

### 7.2 家具和道具数据化到刚好够用

移除 `tableBowl` 单例、固定 `(277,241)` 和 activity z=3080 的专用假设。用家具定义的 front/back/depth 与 seat props 计算桌面道具和手臂层级；同一席的食物类型控制对应道具。

首版只泛化桌子/风铃所需结构，不建立通用编辑器。风铃属于墙面装饰，三个位置默认不改变地面障碍；摆放后通过角色台词/表情产生反应，不用假称它改变了行走路线。

新增读书/浇花必须有书/水壶、手型、接触点和相应反馈；不能只把 eat 改名。复杂转身暂不做，现有 `mirror: never` 保留。

### 7.3 内容定义与玩法随机分离

内容表包含稳定 ID、双语文本键、触发情境、参与者条件、静态动作/道具 ID、冷却和奖励引用；构建校验重复 ID、缺语言、缺资源、过长文案、不可达阶段和循环未终止。

首版用有限枚举和类型化数据，不引入任意条件表达式或脚本执行。角色偏好从 world.ts 移至经过校验的目录，不把生活性格和角色美术骨架强绑在一起。

角色选择/导航/调主题不能消耗模拟随机数。剧情分支用可回放的规则状态决定；装饰摇摆、气泡微动等只用视觉域或派生相位。重启从持久事件阶段继续，不由 renderer 动画播放完成来判定奖励。

### 7.4 资源预算与按需加载时机

现有硬边界继续保留：frame 初始化最多 160 张、单张最多 8 MiB、frame bundle 最多 1200 KiB；当前画布采样保留像素预算和 DPR 处理。

0.4 建议增量预算为不超过 10 张运行纹理，PNG 压缩增量目标 ≤2 MiB、估算解码增量 ≤8 MiB；这是待实测的项目预算，不是已经达到的性能结果。若为七人补手型导致超出，应先减少重复图或提前完成按需加载，不能直接上调限制。

`scene/desk.png` 和 `scene/table.png` 当前绘制只使用其前后片。可列为资源清理候选，但移除前须检索开发预览、生成脚本和包内引用；保留源资产，并同步修改固定 130 张断言。不能只因正式 renderer 不引用就直接删图。

0.5 内容扩充前推进资源按需管理：

1. 资源 manifest 始终完整且校验，先加载当前场景/在场角色/所需活动。
2. 父页按资源组缓存，frame 增量加载采用 assetRevision/请求代次；完成一组后才切换可见角色。
3. 共享纹理引用计数，先卸 rig 再释放纹理；隐藏销毁 frame 后释放 GPU 资源。
4. 处理途中卸载、旧加载结果迟到、失败回退、快速反复换人，保留上一个可用画面或明确加载态。
5. 同时检查 Host Buffer、父页 ArrayBuffer、传输副本和 GPU 解码四层，避免只减少一层却宣称内存下降。

## 8. UI 实施方案

### 8.1 保留视觉方向，修正原型缺口

沿用暖纸 `#F7F2E7`、深蓝灰 `#202D3B`、旧金 `#BA9D68`、自然绿 `#456C65`，保留七位角色的当前生产美术。静态原型用于信息架构和风格，不直接复制其 demo 状态逻辑。

本次逐图/源码阅读发现：

| 原型问题 | 生产处理 |
| --- | --- |
| 夜色图的标题、主按钮文字和部分操作过暗 | app 根显式绑定 `color: var(--ink)`，逐项测文字/按钮对比；不要仅在祖先 body 设置颜色 |
| 窄卡大量 9–11px 文字和小图标按钮 | 正文 14–16px、辅助原则上 ≥12px、操作命中至少 40px；缩减文字而不是继续缩字号 |
| 茶会是固定蓝鲸/Claude，点击 finish 直接设 done | 连接真实参与者选择、行走、对话阶段和持久化回执 |
| 完成状态里第一步仍可能显示“1” | 进度统一由权威事件 view model 派生，不能从 tea/done 两个演示布尔值分别拼装 |
| “编辑暂停”仅为说明，原型没有真实模拟 | 实际增加独立 pause reason，覆盖进入/退出/异常/隐藏 |
| 风铃、人物位置使用百分比 | 用真实世界坐标和统一 viewport，生产场景不能照搬示意坐标 |
| 照片是参考角色绘入 Canvas | 0.5 导出真正的渲染快照；0.4 隐藏拍照可执行入口 |
| 示例管理、点心、错误等以 toast/模态演示 | 只有接入真实命令的动作才可执行，其他不展示 |
| `innerHTML` 拼模板 | React 文本节点和受控图标；内容表、用户文字不能进入 HTML 字符串 |

### 8.2 一个 shell、两种布局

优先用一个稳定的 `VillageShell`/`WorldViewport` 和 iframe，通过 CSS/几何改变浮卡与展开；避免 React 分支切换导致 iframe 重建。如果确实必须重建，先解绑旧 bridge/frame，再挂新实例，期间暂停模拟，任何时刻只有一个有效 frame。

| 模式 | 规则 |
| --- | --- |
| 浮卡 | 基准 340×620，兼容 340×440；四入口，主场景优先 |
| 展开 | 1080×760 为设计基准，实际限制在宿主可用区域；不创建原生窗口或第二 Conversation root |
| ≥900px 可用宽 | 世界 + 300–340px 右侧详情 |
| 560–899px | 单层抽屉；不缩窄到角色无法点击 |
| <560px | 全卡详情；被详情完全遮住的舞台停止模拟，开始事件后返回世界展示过程 |
| 极短高度 | 显示真实空间不足提示和展开/收起入口；暂停，不裁掉操作按钮继续跑 |

`scene-obscured` 用于完全遮住场景的详情；`layout-edit` 用于布置；`commit-pending` 用于关键保存。用户暂停继续由 user 控制。每个界面退出只移除自己的原因；暂停期间仍可进行纯导航和经过专门校验的编辑确认，不能把「模拟暂停」等同于「所有按钮不可用」。

展开适配必须同时考虑当前 `bounds.width >= 764` 的浮卡限制：不能继续把展开是否可见绑在同一个窄屏判断上。分离「宿主允许展示」与「浮卡/展开几何」。主面板切换、sidebar、Live2D 让位仍生效。

展开区域默认限定在对话内容空间，避开主输入框；空间不足时降为抽屉/卡内页。Git 保持打开及其状态，不重复添加对话留白、不修改 Git 数据。先验证已有公开布局标记能完成；如确需协调轨道协议，再最小修改相关插件的展示适配，并补共存回归。

### 8.3 四入口的 0.4 范围

| 页面 | 首版实际内容 |
| --- | --- |
| 世界 | 暂停、展开、更多；模拟时段；最多一条心愿摘要；最多两条气泡 |
| 伙伴 | 七人列表、在场管理、当前活动、性格/已知偏好、问候、邀请 |
| 心愿 | 一条下午茶；选两人/食物；可开始/前往/交流/待确认/完成/失败原因 |
| 布置 | 一件风铃、三个槽位；预览/撤销/确认；未解锁时连接对应心愿 |
| 手账 | 首次同桌见闻与风铃收藏，重复事件汇总；相册待 0.5 |
| 设置 | 主题跟随/浅/深、减少动态、气泡提示开关；其余仅在实际支持时提供 |
| 存档与诊断 | 最近已提交状态、待确认、占用/冲突原因、现有 previous 恢复确认；revision 留在此处 |

点心先作为茶会选择实现。独立「赠点心」按钮只有在具备真实表情/道具反馈与冷却后才开放，不强迫为了凑原型页面而添加假功能。0.4 不展示未实现的音效、Agent、自由旋转或照片按钮。

偏好建议独立 profile 范围 settings 文档，有 schema/revision 与原子保存；只含主题/动效/提示，不装游戏解锁。若复用官方设置服务，先验证保存不会重建世界 owner。用户暂停继续留在 world，避免双份事实。

### 8.4 布置事务

进入布置先等待已有关键保存完成，读取 committed layout 和 layoutRevision，创建内存草稿；模拟暂停但预览可以绘制。pointermove/槽位切换只改草稿，不保存。

确认依次核验：当前 profile/epoch、解锁、slot 白名单、layoutRevision、场景版本与角色/占用安全。写入时使用保存队列最新的 expectedRevision，不把一次无关检查点误当布局冲突；布局本身被恢复/更改时必须重新检查草稿。

确认成功才替换已提交位置并退出编辑；失败保留草稿与原因。Esc/撤销只还原本次草稿。sidebar 隐藏时同进程保留草稿，回来重检；进程关闭不承诺保存未确认草稿。恢复存档、profile 改变或放弃后清除失效草稿。

### 8.5 坐标、气泡、键盘与焦点

- 当前背景使用 cover、交互舞台使用 contain。DOM 气泡必须跟随舞台变换，不能套背景比例。
- frame layout 发布 viewportRevision、CSS 视口、世界矩阵/裁切范围和采样 DPR；父页在 iframe 的 CSS rect 中投影。DPR 不应被再次乘入 CSS 位置。
- 旧视口代次消息丢弃；拖动时气泡跟随实际拖动位置。限两条，避开 HUD，越界时收拢；长文本在详情提供可读副本。
- 继续使用 5 CSS px 阈值。tap 在未进入拖拽的 pointerup 判定，由 controller 核验，frame 不另造一套点击决定。
- 不自动聚焦主游戏；显式点击/Tab 进入后提供局部键盘操作。选择、邀请、食物、摆放均可用表单/按钮完成。
- Esc 由当前交互栈最内层消费一次；先取消拖动/本次预览，模态出现时由模态优先处理，再详情、展开；父页与 iframe 不重复处理同一动作。
- `isComposing` 时不抢 Escape/Enter；关闭详情回到仍存在的逻辑入口。保留主聊天草稿、附件、滚动、输入法和审批快捷键。
- runtime 目前每次模拟更新都会 emit。拆分高频 frame view 与低频 UI selector，避免四个内容面板随 30Hz 全量重渲染；不增加第二时钟。

| M3 双人茶会规则 | 两席同时预留、抵达同步、对话阶段、取消/拖动/阻路、完成解锁 | M2、双座几何 | 不依赖 Pixi 的闭环可回放；完成一次且释放全部预留 | 大 |

关键路径：M0 → M1 → M2 → M3 → M4 → M5 → M6。M1 的文案/样张与 M2 的实现可以在契约稳定后交错推进，但不让多项功能同时改世界模型。这里不要求启动并行代理。

建议按工作包拆成小提交/评审单元；不把生成资源、存档协议和整套 UI 混成一个难以回退的大改动。M4 若仍过大，可先接茶会/手账，再接风铃和展开，均使用同一运行实例。

投入评估用实际产物校准：M0 完成后估算双座与展开风险，M3 完成后再估剩余 UI/资产工作。M2/M3 是主要技术成本，七人接触配准与双语内容是主要内容成本。若需要压缩范围，优先减少专属剧情分支和装饰数量，保留完整闭环、两模式与持久化质量。

| 0.6 | 我的小院：家具合法锚点移动、布局模板与草稿确认，读书/浇花等生活玩法，少量配饰、两套环境主题 | 家具/占用数据化与迁移成熟 | 改变布局后路径/活动真实变化；旧档迁移、撤销和重载一致 |

0.5 数量是目标上限，需要按内容试玩节奏逐批交付；不是要求一次把每种组合都生产完。共同经历先用「见面/一起活动/熟悉」阶段，不采用每日下降的好感条。

照片单独设计：显式进入、`photo` 暂停、隐藏 HUD、有限取景、受限 PNG 字节通道、父页下载。相册保留独立文件、容量上限和有界索引，删除照片不删剧情发现；不经 64KiB world 请求传图，不开放任意文件路径，不自动发主聊天或网络。

工作联动先做一次小型只读适配验证，核对固定官方版本实际公开 API；附件列举的 jobs/session/goal 等服务不作为已验证可直接注入的事实。只传粗状态/计数，默认关闭，不读对话，不干预任务，不按 token/工作时长发游戏奖励。

## 12. 验证与发布门槛

### 12.1 行为与持久化

| 测试域 | 必须覆盖 |
| --- | --- |
| 茶会规则 | 1 人不可开始；任意两名在场角色/两类食物；两席同时获取；第三人占座；到齐才交流；阶段结束释放 |
| 确定性 | 同规则版本、同 seed、同输入 tick 序列结果一致；不同渲染刷新率在同一模拟 tick 上结果一致 |
| 阻路与取消 | 有限重试后结束；拖拽暂挂两人时钟；取消/非法落点保持事件；有效落点/移出解除双方占用 |
| 迁移 | 真实 schema1/2/3 字节→schema4；scene1→2；位置/route/seat/剩余时间合法，旧字节不变 |
| 恢复和回收 | current/previous、混合版本目录、损坏指针、新版拒读、升级前保护引用超过 32 次保存仍可恢复 |
| 提交故障 | 完成前、写快照后、写 current 前后中断；ACK 丢失、重复命令、owner 丢失、epoch 更换、外部 revision 冲突 |
| 奖励一致性 | 完成/手账/解锁同提交；未 committed 不可摆放；重载与重玩不重复首次奖励 |
| 布置 | 草稿不污染 world；confirm 校验布局版本和解锁；cancel 不回滚其他进度；隐藏恢复草稿/版本变化重检 |
| 容量与输入 | 最坏有界状态 + 中文文本 + 封装按 UTF-8 字节测量；非法 ID、重复参与者、过期引用、NaN/超范围拒绝 |

事件所有 21 个角色组合可用纯逻辑参数化测试覆盖；关键组合、角色宽度/配饰差异和七人拥挤场景另做视觉验收。不要把「单次固定随机运行没卡住」当成所有组合都可用。

### 12.2 浏览器与真实 Desktop

- 340×620、340×440、1080×760、800×600；DPR 1/2 及 Windows 100/125/150/200% 缩放。小于最小舞台时应暂停并提供入口。
- 中英长文、深浅主题、Tab 顺序、读屏名称、减少动态；拍照功能未交付前不作为 0.4 假入口验收。
- 浮卡↔展开 50 次、sidebar 50 次、切会话/Git/Live2D、断连重连；同 world、同 owner，不累积 iframe/observer/listener。
- 隐藏时模拟 ticks 和绘制停止；保留必要租约心跳，不能把隐藏 CPU 要求写成绝对零。
- 旧 frame 的迟到消息、无效 token/source/version/sequence 和旧 viewportRevision 不起作用。
- 主聊天草稿、附件、滚动、中文 IME 候选窗、局部 Esc 与真实审批快捷键；fixture 通过不能代替人工系统输入验收。
- 离线运行、无外部请求、无 pageerror；资源损坏/缺失明确失败，不自动联网补图。
- 隔离 profile 安装最终 tgz → 完整重启 → 操作茶会和布置 → 再次完整重启 → 校验持久结果。核对 Host/Client/frame/资源与包的字节身份。
- 停用/启用至少 3 轮；新世界与升级旧世界都通过。不安装到日常 DSH_HOME。

### 12.3 性能与玩法

性能采用同机、同视口、同 resident roster、同负载前后对照：基线、单人、七人自主、七人茶会、展开、隐藏、反复切换。记录 FPS、帧耗时 p50/p95/max、父页 UI 更新、CPU、进程内存、GPU/纹理估算，区分宿主总量和插件增量。

建议门槛：新增每帧 JS 工作 p95 增量目标 ≤1ms；稳定资源数量不随 50 次切换单调增长；同条件 FPS/CPU 较基线恶化超过 10% 时定位后再放行。阈值是项目验收建议，须 M0 采样确认噪声范围。历史 15 秒约 25.9FPS/单核 19.54% 仅作背景，不作为本次实测或跨机器保证。

纯模拟保留七人 108000 ticks（一小时）测试；真实 Desktop 另做至少一小时可见/隐藏交替采样及主工作并行观察。真实任务负载使用隔离测试环境中的既有/明确安排任务，规划和验收脚本不自行发起付费模型调用。睡眠唤醒及物理窗口调整单列现场证据。

玩法评审建议使用至少 3 位未读设计文档的试玩者：能自行找到心愿、选人/食物、看懂事件结果并摆放风铃；能指出小院的变化；能在任意一步离开并理解回来后的状态。未达到时优先修提示与反馈，不用增加内容数量掩盖流程不清。

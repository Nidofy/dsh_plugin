## 1. 目标与非目标

### 1.1 唯一目标

把现有“标题/表单/画布/常驻内容区”的纵向布局，改为：

**同一游戏视口 + 少量悬浮 HUD + 四入口可收起管理层 + 明确的布置/拍照模式。**

不删除 0.6.1 已有内容，不新增另一套游戏模拟，不让改 UI 成为自由装修、LLM 聊天或第二场景项目。

### 1.2 必须保留的既有能力（代码及仓库说明已存在）

- 七位居民、入住/离开、当前居民选择、自主行为、角色拖动、8 类单人活动和包含茶会在内的 6 类双人活动。
- 六项心愿、12 类首次回忆、关系记录；重复体验保留首次事实、不重复发放装饰。
- 三种布局、四个家具位置组各两个锚点、生活角落的三种类型、20 步布置撤销；风铃/纸灯笼/花叶挂饰的挂点与收起。
- 暖阳午后/暮色灯火；七位居民分别记住布艺结/叶形胸针/不佩戴。
- 真实 720×960 PNG、取景、日期/边框、导出、本地相册与删除确认。原上限：20 张、40 MiB、单张 4 MiB。
- 中文/English、浅色/深色/跟随系统、减少动态、角色气泡。
- schema 6 / scene 3 / rules 3 / content 3、历史迁移、世界单写入者、CAS、未知回执只读核对、资源白名单与离线机制。
- 右侧浮卡/宿主内展开、Git/Hg 共存、Live2D 互斥、完整 composer 避让、隐藏暂停和同进程草稿保留。

### 1.3 本轮不做

自由 XY/网格装修、家具复制/旋转/镜像、删除基础桌椅、第二张地图、角色增减、复杂换装、天气/音效、货币/体力/抽卡/离线收益、真实模型对话、真实 Agent 状态映射、Notebook/桌宠联动、原生窗口置顶/最小化、新建 Electron 窗口、第二 root 或第二世界 writer。

不能用“功能即将上线”的占位按钮补空白；不能用“成功”toast 代替未实现操作。

## 3. 整体布局与尺寸

所有数字均为 **CSS px**。截图的物理像素尺寸不直接当成 CSS 视口尺寸。继承宿主计算出的可用区域，不强制把宿主窗口改成标定尺寸。

### 3.1 常态结构

```text
┌──────────────────────────────┐
│ [消息] [第1天 · 14:46] [暂停][更多] │  窄窗顶部悬浮，无标题底板
│                              │
│      原有小院 / 居民 / 家具       │  同一个 iframe 填满内部
│                              │
│   [新回忆已记入手账 · 查看]       │  仅事件发生时出现
│                              │
│ [居民] [心愿] [布置] [手账]       │  底部悬浮 Dock
└──────────────────────────────┘
```

### 3.2 响应式规则

| 插件内部宽度/高度 | 规则 |
|---|---|
| W < 320 或 H < 360 | 保留既有空间不足暂停；只显示可读解释、调整显示和关闭，不压缩成不可用游戏 |
| 320 ≤ W < 560 | 紧凑 HUD：消息、时间、暂停、更多；底部抽屉 |
| 560 ≤ W < 900 | 消息/时间在左；暂停、拍照、视角、展开/收起、设置、关闭在右；底部抽屉 |
| W ≥ 900 | 同上；管理内容改为右侧面板，宽 360，右 12，顶 72，底 12；Dock 左下 |
| 360 ≤ H < 480 | 短高模式：抽屉打开即深展开，隐藏次要说明；编辑用折叠选择器，不压缩按钮 |

窗口大小的判断用插件内部尺寸；不能用浏览器 innerWidth 替代所有断点。现有 `floating-layout.ts` 的宿主可见性与 composer 避让仍是外层边界。

### 3.3 固定参数

- 外边距 12；短高可降为 8，但命中区域不缩小。
- HUD 图标 20，命中框 40×40，间隔 6；顶部 y=12。窄窗时间宽度上限 124，字 12；显示“第1天 · 14:46”，省略“小院”二字。
- 暂停按钮始终常驻；窄窗“更多”依次列出：拍照、视角、展开/收起小院、设置、关闭小院。每行高 44，图标+文字。
- 宽窗这六项以图标直接显示，不重复出现“更多”。“关闭”只关闭小院，不退出 DSH。
- Dock 高 56；宽 `min(W−24, 352)`；下边距 12；窄/中宽居中，宽窗左边距 12。每项图标 20 + 文字 12，不能仅图标。
- 半展开抽屉总高 `min(360, floor(0.48 × H))`；深展开总高 `H−84`；宽 `min(W−24, 480)`。包括标题、内容和底部 Dock，不重复渲染两份 Tab。
- 抽屉顶栏 40：当前页标题、深展开/还原、收起。内容区域单独滚动；没有外层整卡滚动。
- 长列表必须有可感知的滚动轨迹/下缘渐隐，键盘可以到达末项。
- 普通抽屉展开/收起不改变 iframe 尺寸、不重置镜头、不重建角色。
- 窄窗抽屉收起后所有页面状态保留；关闭小院重开默认 Dock 收起，并保留最后一次选择的 Tab（仅同进程）。
- 340×720、580×720、1080×760 是三张视觉标定图；另测 320×360、340×480、800×600、宿主 800×440 等。

### 3.4 打开/关闭规则

点击未展开的 Tab → 半展开该页；点击当前展开 Tab → 收起；点击另一 Tab → 保持展开高度切页。顶栏明确提供“收起”。抽屉外的空白单击只收起抽屉/轻浮层，不顺带触发场景操作。点击场景内居民是明确目标：收起普通抽屉，再选中并显示居民卡。开始拖动则执行拖动，不触发单击。

鼠标 hover 不自动展开 Dock；不要因为路过底部或离开底部而反复开关。

## 4. 视觉规范

### 4.1 主题 token

| Token | 浅色 | 深色 |
|---|---|---|
| 主文字 | `#34473C` | `#EEF0DF` |
| 次文字 | `#626E60` | `#BAC5B3` |
| 强调 | `#456740` | `#B8CCA2` |
| HUD 底 | `rgba(250,247,240,.90)` | `rgba(36,47,42,.92)` |
| 面板底 | `rgba(255,252,245,.96)` | `rgba(40,53,46,.96)` |
| 实色降级底 | `#FFFCF5` | `#28352E` |
| 分隔线 | `#D5D5C5` | `#54624F` |
| 轻选中底 | `#E9EEDD` | `#35473A` |
| 危险/失败 | `#A33D32` | `#FFB4A8` |
| 焦点框 | `#946A20` | `#E2C16E` |

HUD blur 8；正文面板 blur 12；圆角：按钮 12、浮层 16、抽屉 20；边框 1。只对小面积前景做 backdrop-filter。不得对整个动态画面挂持续实时模糊。

新增“减少透明效果”设置；启用、浏览器不支持或视觉/性能测试不达标时使用同套实色 token。减少透明不能改变布局或隐藏功能。系统/用户原有主题偏好保留，不能迁移时改成浅色。

### 4.2 排版与动画

正文 14/1.5，辅助字 12/1.5，面板标题 18/1.35；删除大块英文装饰眉题和重复介绍段。角色名称可加粗，不使用过重标题字体。所有主操作至少 40 高；布置保存/拍摄等至少 44 高。

面板开合 180ms ease-out；轻提示 140ms；镜头平滑恢复 180ms；tooltip 延迟 350ms，键盘 focus 同样显示。减少动态时所有上述过渡为 0，不新增弹跳、粒子或全屏变暗脉冲。

普通文字对比目标 ≥4.5:1，焦点与关键轮廓目标 ≥3:1；实际叠加背景后检查。不能以“加文字阴影”代替对比度控制。

### 4.3 图标与头像

扩展已有 `Icon.tsx` 的仓库自制 SVG，统一 20×20、线宽 1.7、圆端点。禁止 emoji 作为正式系统按钮、外网图标字体、新 UI 组件库。

居民列表头像使用批准纸娃娃素材合成的完整头部/上半身（头发、发饰、脸同在），预渲染透明 PNG 128×128，UI 显示 44×44。不得继续直接展示 `parts/face-neutral.png` 单层。只合成现有资产，不重绘或改变角色人设。头像离线构建、白名单登记；不是七个额外 Pixi 实例，也不为头像常驻动画。

## 5. 场景、比例与镜头

### 5.1 当前代码事实与必要修正

当前 `frame/viewport.ts` 对世界用 contain，对独立 backdrop 用 cover；外层又把 canvas 限为 3:4。直接取消外层比例限制后，这两个变换会在任意窗口比例下明显分离。因此本次不能只改 CSS。

世界仍是 **360×480 逻辑单位**。背景中的真实场景、家具、角色、挂饰、阴影、点击区必须使用同一世界投影。额外满幅背景只能是明确的非交互氛围延展，不得伪装成新增可行走区域。

### 5.2 固定实现

层 0 是复用批准背景得到的低频氛围延展：只填满视口，不含可识别的重复人物/家具、不接受交互。在资源加载/尺寸或环境改变时缓存生成，低分辨率上限 512×512；不每帧生成或模糊。允许最多增加 1 张临时缓存纹理，隐藏/卸载释放。

层 1 是真实完整世界：背景与所有游戏对象共同变换。全景初始比例：

```ts
s0 = Math.min(workspace.width / 360, workspace.height / 480)
s  = s0 * zoom                       // zoom ∈ [1, 1.5]
// 世界小于 workspace 的轴居中；大于该轴时平移夹在 [长度差, 0] 内。
// x/y = workspace 原点 + 居中或夹紧后的平移。
```

观察模式 workspace 为整个插件视口。普通内容抽屉不改变 workspace。编辑模式显式换为未被编辑栏覆盖的工作区，并保存/退出后恢复观察相机。照片模式使用单独取景区与照片相机。HUD 的 CSS 大小不参与世界缩放。

非交互延展与真实世界边缘用 24px 柔和淡化衔接；只在世界外缘处理，不模糊人物或文字。不得重复铺贴明显门窗、拉伸人物、修改场景世界尺寸来填屏。

### 5.3 操作

- 滚轮只在裸场景内缩放；`Ctrl/Meta+Wheel` 不劫持浏览器缩放。普通滚轮的 deltaMode 归一化后限幅，锚定鼠标下世界点。
- 当前没有角色/家具拖动时，空白左键拖动平移；也支持鼠标中键，或 Canvas 获焦时 Space+左键。
- zoom=1 且某轴全景已适配时，该轴不平移。非法/过量平移自动夹紧。
- 角色拖动、家具拖动、范围滑块、列表滚动优先于镜头；拖动期间滚轮不改变世界投影。
- “视角”浮层提供 `− / 百分比 / + / 恢复全景`，一行可点；缩放时相同控件临时浮现，停止 2 秒后隐藏，键盘焦点在内时不自动隐藏。无常驻纵向滑轨。
- `+` / `−` 每次改变 0.1，恢复为 zoom=1、平移=0。相机不写世界存档；隐藏同进程保留，重启回全景。
- resize、DPR、展开/收起宿主几何改变时取消当前指针手势，重算投影，递增 viewportRevision；不提交半完成拖动，不改变世界坐标。

### 5.4 普通抽屉遮挡

抽屉是覆盖层，不是挤压场景的布局行。“看看”动作收起抽屉并聚焦目标；不要为每次开关抽屉突然改变世界比例。布置与拍照属于显式模式转换，允许进入专用构图。

## 6. 四个主入口的完整内容

### 6.1 居民

顶部显示“在场 n/7”和“安排入住”。默认列在场居民：完整头像、名称、一行真实游戏状态、“看看”。“安排入住”在同一面板内显示七人复选项和“全员入住 / 仅留当前”；至少保留一位的原约束不变。未在场人物不能通过普通“看看”悄悄替换当前居民。

点击角色/看看后：选中现有 world.actor；显示锚定角色的轻卡，宽 220（窄窗夹在12px安全边内），包含名字、状态和“互动”按钮。轻卡不主动发起活动。主面板详情分为“日常互动”和“共同经历”；八个单人活动来自现有目录，禁用时显示原因（缺少布局、正在活动、冷却、保存处理中等）。

“配饰”快捷入口跳到“布置 → 氛围”的目标居民，但不直接写世界。共同经历只展示现有 bonds，不造好感度数值。

### 6.2 心愿

二级仅“心愿 / 一起活动”。心愿页显示既有六项、完成状态和对应操作入口；无截止时间、红点催促、领取货币按钮。“一起活动”包含热茶/白米饭同桌和现有五种邻里双人活动；参与者必须为在场不同居民。

进行中的活动使用一张置顶状态卡：名称、参与者、阶段、“取消活动”。错误按实际 code 映射，不能把所有 `actionError` 都解释为“通路被占”。缺布局、活动冲突、保存未确认各自明确。

### 6.3 布置

二级固定“家具 / 挂饰 / 氛围”。

- 家具：三种模板；四个位置组（书桌/餐桌/长椅/生活角落）；生活角落的坐垫/书架/盆栽是互斥类型，不是同时新增三件家具。六类目录以可识别缩略图展示。
- 挂饰：风铃、纸灯笼、花叶挂饰；未解锁显示现有解锁条件；已解锁可选三个挂点或收起。
- 氛围：环境两项与目标居民配饰三项。明确“环境不影响界面主题”。

查看布置页不暂停；点击“开始布置”或某项“调整”才进入模式。模板、环境、配饰走同一个 Home 草稿/撤销/确认链；挂饰沿用独立挂饰草稿。不同草稿不能并存，切换必须先保存或明确放弃当前草稿。删除原页面中重复的“确认布局”直写入口，统一从模板进入 Home 草稿。

### 6.4 手账

二级固定“回忆 / 相册”。回忆整合 `world.journal` 和 `world.neighborhood.memories`，按首次发生时间倒序；同源首次茶会只显示一次。保留首次参与者/时间和重复计数。

相册保留容量信息、真实缩略图、标题、查看、导出、删除确认。照片与手账互不删除。相册里的“拍一张”进入同一 Photo 模式，不新建页面、iframe 或世界。

## 7. 通知与消息中心

### 7.1 事实来源

本轮新增的是消息“呈现层”，不是新玩法。`deriveNotices(confirmedWorld)` 只从已成功保存的首次茶会与邻里回忆派生；装饰解锁作为对应回忆的附加信息合并到同一条。稳定 ID 包含事实类型、story/template ID 和原始 eventId；不把可增长 count 当新 ID。

不为普通吃饭/散步、重复活动、换页、预览摆放、照片导出生成永久消息。照片保存使用一次性反馈，相册本身是记录。系统故障是状态，不混入可全部已读的趣味消息。

在 world candidate 尚未 committed、保存超时或 ACK 丢失时，不能显示“新回忆已保存”“已解锁”。只有既有只读核对确认成功后才发布一次。

### 7.2 未读

入口始终存在；无未读无数字，有未读显示数字，上限视觉 `9+`，可访问标签报实际数量。打开消息面板不等于已读；查看具体消息并成功定位详情后标记，或点击“全部已读”。无“清空历史”按钮。

已读状态放在显示偏好，不放 world。为持久未读，允许偏好 schema 1→2 的一次窄迁移：保留旧字段，增加 `reducedTransparency`、`noticeReadIds`（最多64个、每个≤96 UTF-8字节）、`noticesInitialized`。世界 schema 不升级。

首次从旧版本进入新 UI：既有回忆进入历史，默认已读，不补弹旧通知。用一次偏好 CAS 写入现有事实 ID 与 initialized=true；未确认前抑制历史 toast，显示“消息状态尚未保存”，不假称初始化完成。读取到已初始化偏好后，缺失于已读集合的真实事实恢复未读。坏档不能静默清空已读/主题，仍保留原件并提示恢复。

### 7.3 面板与 toast

消息面板左上锚定，宽 `min(320,W−24)`，高 `min(360,H−96)`。顶部“消息 / 全部已读”；列表通常3条，空间允许4条；底部“查看手账”。小高度宁可减少可见条数，也不缩字。列表滚轮不触发相机。

toast 宽 `min(320,W−24)`，底在 Dock/抽屉上缘12px，最多一条；显示5秒，hover或键盘聚焦暂停倒计时。3秒内同批新事实合并为“新增 n 段回忆”，只保留有界待展示ID集合（上限16）；在拖动、布置、拍照、错误处理时不弹，退出后合并一次。超出队列的事实仍在消息中心，不能丢失记录。

消失不标已读；消息入口强调一次，无飞行动画。点击通知打开手账对应事实；不存在已在场角色时不强制召回/入住。没有目标事实时不显示虚构成功页。

## 8. 布置模式：受控锚点，而非自由装修

### 8.1 进入与工具区

进入调用现有 `beginHome()` 或挂饰预览入口，添加 `arrange` 原因；观察模式 camera 先缓存。已有剧情活动时拒绝进入，并展示“先结束或取消当前活动”。不能自动取消剧情、移动居民或改 RNG。

普通 Dock 替换为编辑托盘：正常高度170；短高110。上方是选中对象与合法位置，底部固定“撤销 / 取消 / 保存布置”。半透明状态条“布置中 · 预览未保存”。短高托盘用44高的对象选择器与44高动作栏，详细选项临时盖在上面；主画面不被永久挤成几十像素。

布置期间居民选择/拖动禁用，普通玩法 Tab、拍照、设置禁用；允许宿主展开/收起和临时隐藏。点击小院关闭时：无更改直接取消草稿并关闭；有更改弹“放弃未保存布置？”；提交 pending/unknown 时不得当成普通草稿丢弃，先核对保存状态。

### 8.2 家具输入

每组仍只允许 `positions[id] ∈ {0,1}`。从既有 `homeScene()`/offsets 计算真实绘制矩形和足迹，不在 UI 手写第二套座位几何。

- 点击家具 → 选中并展示两处锚点；列表选择同等有效。
- 按住拖动阈值5 CSS px；按下不移动正式草稿。显示清晰78% ghost与落点反馈。
- 到最近合法锚点中心26 CSS px内可吸附；同距取较小索引。若现有校验拒绝，标记“此处被占用”，不能仅显示红圈。
- pointermove 只更新手势预览；pointerup 在合法位置才调用一次 `updateHome()`，构成一步 undo。非法放下回到上一有效草稿，无新增 undo；同一位置不新增 undo。
- pointercancel、失焦、resize 或手势中隐藏仅撤销本次未落定移动，不丢掉之前有效的布局草稿。
- 点击空地不保存布置；Enter 只在明确保存按钮或已选锚点控制获焦时按其语义执行，不设全局“Enter保存”。

基础四组不提供“收回/删除/复制/旋转/翻转”。生活角落切换是已有 layout 切换。3种模板×2⁴位置组合共48个，全部旧几何规则继续适用。

### 8.3 挂饰输入

只使用现有窗边/门旁/院墙及收起。挂点有图标与文字，可拖向挂点，也可按按钮选择；挂点吸附半径26 CSS px。挂饰“收起”是明确操作，不能把拖到画布外解释成删除。

挂饰使用现有各自草稿与提交函数，不伪装成 Home undo 支持；挂饰托盘不显示不可用的撤销按钮。挂饰之间或 Home/挂饰之间切换前先结束当前草稿。

### 8.4 事务与生命周期

保存始终复核布局 revision、活动、居民位置和 safe 位置。失败保持草稿和解释，不瞬移居民。成功后退出编辑、恢复观察相机，仅移除 arrange，不移除 user/photo/disconnected 等其他原因。

临时 sidebar/宿主面板隐藏保留 runtime 中的有效草稿，返回重检；显式取消、确认放弃后关闭、真正换连接/身份或页面离开按既有清理逻辑执行。不得把普通组件 unmount 当成玩家取消。

“家具变化后居民反应”本轮只保留已有风铃反应与活动结果，不新增每次更换家具的剧情文案或状态推进。

## 9. 拍照与相册

沿用 `enterPhoto()` / `exitPhoto()` / `capturePhoto()` / album，禁止新增第二模拟器。拍照进入前沿用现有 flush 确认；只增加/移除 photo 原因。原 userPaused 不能被退出拍照清掉。

拍照时隐藏普通 HUD、Dock、气泡、选中光圈与编辑标记；只保留“退出拍照”、取景工具和拍摄按钮。拍照操作层仍是 DOM，不写入 PNG。预览、保存相册、导出 PNG 三者语义保留。

**本次必须同步修正取景导出**：现有 capture 是从当前 app.canvas 居中截取。取消3:4外层限制后不能继续把整宽窗结果直接裁成照片。使用当前同一 renderer 的一次性规范3:4离屏渲染，固定导出720×960，服从 photoOptions，而不是观察 camera。不得新建常驻 Application/ticker。相同冻结世界和取景参数在不同宿主尺寸下应得到相同内容构图；退出后恢复观察 camera。

照片仍包含实际已保存家具/配饰/环境，不包含未确认草稿、氛围延展重复图、HTML文字或额外人物。保留文件上限、导出、安全删除、Blob URL回收和CAS故障处理。

## 10. 设置、运行状态与错误

设置为插件内部浮层，宽 `min(360,W−24)`，高≤H−24，单列分组；不切左右导航，不覆盖插件外的聊天输入。组固定为：

1. **显示与交互**：主题、语言、减少动态、减少透明、角色气泡。
2. **视角与操作**：恢复全景、鼠标/键盘说明。
3. **运行与存档**：有效暂停原因、最近确认修订、保存状态、清理警告；展开“开发与恢复”才出现原有恢复动作。

设置变更自动提交现有偏好CAS。pending显示保存中并暂时锁冲突输入；unknown先只读核对；成功才更新“已保存”。读取/写入偏好与世界各自事务不能混为一条，不因标已读产生世界存档。

正常运行不显示存档rN。用户暂停时显示“已暂停”；布置/拍照显示自己的模式；其他暂停原因要说明真正阻塞原因，不能把按钮写成“继续”却暗示能恢复断连世界。

保存失败、结果未确认、世界占用、断连、资源缺失、布局冲突有独立文案及操作。重大错误用持续错误卡，不自动5秒消失，不在照片里，不用通知“全部已读”清除。原始诊断码放可展开详情，正常文案中不暴露路径/token。

## 11. 层级、输入与可访问性

### 11.1 层级（仅小院内部 stacking context）

```text
0 atmosphere / 10 world iframe / 20 scene labels
30 HUD & Dock / 40 drawer or inspector / 50 popover
60 settings or photo preview / 70 confirm/error / 80 tooltip
```

重要错误与确认期间不显示普通toast。相互遮挡的普通主面板同一时刻只开一个：消息/更多/视角打开时收起普通管理抽屉；设置替换其他普通浮层并记住返回状态。居民小卡与普通浮层互斥。布置/拍照期间不打开普通面板。

根覆盖层 `pointer-events:none`，实际控件 `pointer-events:auto`；游戏iframe接收世界输入。不得用透明全屏div无条件吞掉场景输入；modal的scrim只覆盖小院本身。点击外部关闭的那次指针事件被消费，不能穿透为拖角色或触发宿主消息发送。

### 11.2 Escape 优先级

在小院焦点域内且不处于 IME composition 时：

1. 当前确认/错误详情或照片预览；
2. 当前未完成角色/家具/镜头手势（回滚本手势）；
3. 消息/更多/视角/居民轻卡；
4. 布置草稿（取消；pending/unknown锁定并提示核对）；
5. 拍照模式；
6. 设置；
7. 展开的管理抽屉；
8. 宿主内展开展示收回紧凑卡；
9. 未消费则留给宿主，不擅自关闭小院或吞审批快捷键。

只在实际消费时 preventDefault/stopPropagation。退出编辑/设置/拍照后焦点回入口；入口因响应式改变不存在时，回对应Dock或更多按钮。抽屉不是全局模态；设置/确认的焦点范围局限小院，关闭后可回主聊天。

所有图标有中英文 aria-label、focus-visible；tabs使用role和方向键；所有拖动都能通过名单/合法位置按钮完成。不要要求长按、hover或记住快捷键才能完成任务。

## 12. 状态所有权与版本边界

### 12.1 唯一状态来源

既有 `VillageRuntime` / `HomeController` / Host SaveStore 继续持有世界；UI只调用命令。不得把world复制到组件state中作为第二权威。

新增 `PresentationState` 归runtime持有，保存同进程的Tab、抽屉档位、浮层、观察camera、编辑选中对象/手势、通知队列。它不是持久世界，不跨会话重建。模式仍从既有 `photoMode` / `arranging` 推导，不另建一个可与runtime冲突的布尔模式。

动画帧走frame订阅；低频UI走现有subscribeUI或专用选择器。不能让React整套面板每一模拟tick重渲染。

### 12.2 允许升级

- 世界保持schema6、scene3、rules3、content3；不改变故事ID、角色ID、坐标或行为规则。
- 偏好仅允许schema1→2，字段与迁移按第7节。
- frame协议仅允许2→3：因为加入camera与布置输入；父端/frame统一版本，严格拒绝旧协议。发布同一包内升级，不改Host公开业务路由。

统一协议定义放`core/frame-protocol.ts`（新）。新增输入仍校验source、null origin、token、sequence、viewportRevision、有限数值、ID白名单、pointerId、当前模式与事务锁。frame不能直接写文件、提交世界或调用任意runtime方法。

## 13. 交付完成的定义

不是“看起来像玻璃面板”即完成。必须同时满足：旧功能均可达、窄窗可用、视觉按标定稿、拖动/滚动不冲突、相机投影正确、保存语义不倒退、隐藏草稿保持、照片构图稳定、宿主输入完整、离线打包与生命周期回归通过。

真实Windows缩放/IME/睡眠/前台GPU与人工观感未测时要写“未测”。仓库注明用户暂缓的一小时真实运行测试不得自动重启，也不能把短时采样改写为已通过。

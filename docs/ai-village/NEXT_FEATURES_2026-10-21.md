# AI 小院下一阶段功能拓展提案

日期：2026-10-21。状态：**调研 + 设计提案，未实施**。
基线：`packages/ai-village` 0.3.2（世界格式 3）、DSH 官方 `0.2.1-rc.2`。
方法：精读 `core/world.ts`、`core/controller.ts`、`frame/scene.ts`、`client/runtime.ts`、`client/Floating.tsx`、`host/*`、`src/definitions.ts` 资源清单、美术与历史文档，并分渲染、模拟、Host/客户端、历史约束四个方向只读调研。

**成本口径（粗估，含代码与测试，不含等待验收）**：S ≈ 1–3 人日；M ≈ 3–7 人日；L ≈ 1–3 周。美术成本单列：无 / 低（复用或程序化）/ 中（1 套新贴图）/ 高（新角色或新场景）。

## 0. 一页速览

**现状**：小院是一个"会自己生活的立体绘本"——7 位居民在 1 个固定场景、3 处家具之间自主工作/吃饭/休息，玩家能做的只有把角色拖到家具上。它很美、很稳（隐藏后 CPU 0.42%、暂停即停），但**没有目标、没有反馈、没有时间感、没有社交、与 DSH 使用没有关联**，属于"看几分钟就关"的观赏型 demo，距离"会重复打开的小游戏"还缺一层玩法设计。

**核心判断**：下一版最高性价比不是加美术资产，而是**在规则与文本层补齐"可读性、目标感、时间感、关联感"**。现有 7 角色、3 种活动、3 个稀缺座位、24px 避让和确定性随机，已经足够组合出排队、围观、争座、串门、事件链等大量"可读剧情"；而美术增量（每角色 +2–3MB、每场景 +6–8MB）会线性推高 27.6MiB 的离线包与 130 张常驻纹理，应放到玩法验证之后。

**建议的版本路线**：

| 版本 | 主题 | 玩法增量 | 美术 | 存档 |
| --- | --- | --- | --- | --- |
| v0.4 | 小院的一天 | 时钟/时段/昼夜/天气、表情符号、轻点互动、台词气泡、卡内设置 | 无–极低 | 不变（v3） |
| v0.5 | 社交剧场 | 需求/心情、关系网、排队/争座/围观/串门、事件链、每日委托、成就图鉴、小院日报 | 无 | v4（新增字段） |
| v0.6 | 我的小院 | 家具摆放/布局模板、新家具活动、第 5 表情、相机缩放、明信片导出、资源惰性化 | 低–中 | v4/v5 |
| v1.0 | 与你同频 | Agent 状态映射（真实忙碌/等待/完成）、完成庆祝、会话联动、声音（可选）、季节皮肤/新场景 | 中–高 | 独立 settings/meta |

**最先要做的三件事**（不改变玩法）：① 补 0.3.2 的真实 Desktop 复验与 README 版本漂移；② 清理 2 张从未被渲染使用的 1.17MB 纹理；③ 设计并预埋 world schema 4 与 frame 协议 v2，避免每个新玩法都撞一次迁移。

## 1. 现状：它现在是一个什么样的"游戏"

### 1.1 当前可玩循环

| 环节 | 玩家能做什么 | 世界会做什么 | 玩家得到的反馈 |
| --- | --- | --- | --- |
| 打开 | 点右上角 ⌂ 入口 | 恢复上次世界；按 30Hz 固定步长继续 | 卡片、场景、状态行 |
| 观察 | 看 | 角色 idle → 按固定偏好选 3 处家具之一 → 走过去 → 用 12–24 秒 → 再选 | 表情、动作、位置变化 |
| 干预 | 拖动角色到家具/地面；Esc 取消 | 拖动期间冻结该角色；落点非法回退；家具独占 | 选中描边、落点提示 |
| 管理 | 选择在场角色 1–7 人、全员入住 | 新成员走位避让，抢空位 | 成员列表、下拉框 |
| 暂停 | 暂停/继续、关闭浮卡 | 停止计时与绘制，进度保留 | 底部状态、保存修订号 |

一句话：**循环只有"看 + 拖"，缺少"为什么打开、打开后要做什么、做完有什么变化"。**

| 平台 | 官方 `0.2.1-rc.2`、Windows x64、单 profile 单世界、无服务端推送 | 在线多人/社区结构性不可行；多窗口只能"占用" |

## 2. 判断：趣味性的五个来源与当前缺口

一个"观赏型小游戏"能否被反复打开，通常取决于五层乐趣。逐层对照现状：

| 乐趣 | 玩家心理 | 现状 | 缺口 |
| --- | --- | --- | --- |
| 观察的乐趣 | "我看得懂它们在干嘛" | 有动作，但没有名字标签、没有状态文字、没有原因 | 看不懂"为什么他去吃饭"，只有 3 种行为 |
| 干预的乐趣 | "我一动手世界就变" | 只有拖拽 | 没有点击、派活、布景、互动反馈 |
| 发现的乐趣 | "居然还有这种事" | 只有随机漫步与选座 | 没有事件、没有台词、没有彩蛋 |
| 积累的乐趣 | "我的小院在变多/变好" | 只有位置与在场名单 | 没有关系、收集、成就、日记 |
| 关联的乐趣 | "它和我的 AI 工作有关" | 完全离线独立 | 发行记录明确未做真实 Agent 状态映射 |

**设计原则**（后文所有提案都按此裁剪）：

1. **规则与文本优先于像素**：能用事件/台词/数值/UI 表达的，不新增美术。
2. **先让"发生了什么"可读**：名字、状态、气泡、日记，是比新动作更便宜的内容。
3. **座位稀缺是现成的戏剧引擎**：3 座 7 人天然产生排队、争抢、围观、串门，把现在的"频繁掉头"噪声变成可读剧情。
4. **确定性不可破坏**：所有新随机用状态派生或第二个 RNG，不改现有 LCG 消费顺序。
5. **旧档可读**：只做新读旧宽容 + 内存迁移；旧客户端读新格式显式失败、不重置。
6. **双模式与生命周期**：新增 UI/监听必须可撤销，隐藏即停、重连不重放一次性反馈。
7. **性能红线**：新增逐帧 JS ≤1ms、纹理 +30 张以内；不得在 frame 内自起 ticker。

## 3. 功能提案

> 每项给出：**卖点 / 玩法 / 实现落点 / 数据与协议 / 成本 / 风险**。★ = 建议优先。

### T1 「小院的一天」——时间与生活节奏

**T1.1 ★ 小院时钟与时段**
卖点：打开就能看到"现在是傍晚，大家快收工了"，同一场景在一天里有不同气氛。
玩法：1 现实分钟 = 1 小院小时（设置可调）；时段分清晨/上午/午后/傍晚/深夜，显示在卡片底部与角色状态里；行为权重随时段变化。
实现：由 `world.ticks` 派生（`world.ts:33`，30 tick/秒），**不新增存档字段**；新增 `src/core/clock.ts` 纯函数。
成本：S，无美术。
风险：暂停时时间自动冻结（现有语义天然正确）；玩家调速度需存设置（独立 settings 文件）。

**T1.2 ★ 时段日程与"今日计划"**
卖点：每个角色有生活节奏，玩家可以预判"上午 Claude 在写东西、午后 Gemini 打盹"。
玩法：以权重表替代硬编码偏好表（`world.ts:151`），按时段 + 角色偏好 + 心情合成选座权重；卡片里展开"今日日程"显示台词化计划。
实现：`src/content/schedule.ts` 数据表；`world.ts` 选座逻辑改为查表。
成本：S–M，无美术。
风险：确定性回归需重跑 `tests/autonomy.spec.ts`（固定 tick 快照会变，属预期）。

**T1.3 昼夜色调与夜间灯光**
卖点：夜晚的小院是暖黄灯光 + 打盹的居民，视觉记忆点强。
玩法：背景/角色统一轻 tint，夜色叠加层，2–3 处暖光；深夜低概率出现"睡不着散步"。
实现：`frame/scene.ts` 的 `layout/paint` 加叠加层，`Graphics` 绘制，不做 Filter；由 ticks 推导。
成本：S，无美术（可选 1 张 glow）。
风险：全屏叠加易脏色，需按已批准原图做色彩 QA；仅影响表现，不入档。

**T1.4 ★ 天气与粒子（落叶/雨/雪/萤火虫/烟花）**
卖点：小院"活"起来，天气与节日成为再次打开的惊喜。
玩法：按小院日期 seed 出天气；雨/雪只做表现 + 少量行为偏好（雨天更爱坐垫）；烟花用于节日/完成庆祝。
实现：对象池 + 1–2 张 16–64px 小贴图（或纯 Graphics），位置/相位由 ticks + 固定 seed 计算；新增 `frame/effects.ts`。
成本：S–M，低美术。
风险：性能（40–160 sprite、+0.2–0.8ms）；禁止每帧 `new`；烟花做成节庆开关。

**T1.5 节日事件与每日彩蛋**
卖点：春节/中秋/万圣节/开发者日，全员特殊行为 + 一句节日台词，形成"节日限定"的回归理由。
玩法：按本地日期触发（只在打开时判定，不追补离线）；场景小装饰 + 全员围观烟花/分月饼。
实现：`src/content/festivals.ts` + 事件系统（见 T2.7）；装饰用 Graphics 或 1–2 张小图。
成本：S–M，低美术。
风险：时区/跨天边界；节日内容需双语；离线不追补。

### T2 「会说话的小院」——表达与社交

**T2.1 ★ 表情气泡与拟声符号**
卖点：角色头顶冒出 `!`、`?`、`❤`、`Zzz`、`♪`，投入感立刻提升一个档位。
玩法：点击、被选中、被打断、完成活动、进入休息等时机显示 1–2 秒符号。
实现：优先**父页 DOM 浮层**：父页已知 360×480 世界与等比缩放公式（`frame/viewport.ts`），可零 bundle 增量地把 world 坐标投影为卡片内像素；备选 Pixi `Graphics`。**不用 Pixi Text**，避免 +50–150KiB bundle 与中文字体问题。
成本：S，极低美术（1 张小图集或纯 Graphics）。
风险：iframe 与父页坐标需在缩放/DPR 下对齐；相机缩放后需 frame 上报变换（先不做相机）。

**T2.2 ★ 预写台词池（角色性格）**
卖点：每个角色有自己的口癖和句子，玩家会为了看台词反复互动。
玩法：按 角色 × 行为 × 时段 × 心情 × 关系 选一句，气泡显示 2–5 秒；**明确是预写台词，不调用模型**。
实现：`src/content/dialogue/<character>.ts` 数据表 + `src/core/dialogue.ts` 选择器（确定性：用 ticks+seed 派生，不占 LCG）；DOM 气泡（同 T2.1）。
成本：M（内容量 + 双语校对），无美术。
风险：文本量是主要成本；需长度限制与内容审查；不得拼接未校验文本进 HTML。

**T2.3 ★ 轻点互动**
卖点：点一下角色会惊讶→开心→说出今天的台词，是最低成本的"玩家存在感"。
玩法：单击（位移 <5px 的 pointerup，当前直接 return，`controller.ts:79-80`）→ 表情 + 气泡 + 小跳；连点有不同反应；不落盘。
实现：`frame/scene.ts` 上报 `tap{actorId,point}`，`controller` 分发，`runtime` 触发表现消息。
成本：S，无美术。
风险：与拖拽阈值冲突（5px）；Esc/焦点/IME 行为不能回归。

**T2.4 ★ 围观与串门**
卖点："Claude 在工作，Gemini 凑过去看"——小院开始有社会。
玩法：idle 决策时以一定概率选择"靠近正在活动的角色"或"去别人旁边"，形成聚落；关系值随之增加。
实现：`world.ts:150-162` 选目标逻辑扩展；复用 walk/idle/表情，不新增 behavior。
成本：M，无美术。
风险：拥挤/抖动；需要"围观位"与 24px 避让配合；确定性测试。

**T2.5 关系网与好感度**
卖点：7 位居民之间 21 条关系，点开关系图能看到谁和谁更亲近，台词随之变化。
玩法：同处/同桌/围观 +，争座/被打断 −；影响串门概率、候位优先级、配对台词。
实现：world schema 4 存 21 个有符号小整数（约 100–200B）；UI 在卡片内。
成本：M，无美术。
风险：数值漂移与存档校验；旧档默认值；不能影响现有活动合法性。

**T2.6 ★ 排队与争座**
卖点：把"3 个座位 7 个人"的稀缺变成可见的排队/争抢/让步，是现有资产下性价比最高的戏剧机制。
玩法：家具被占时进入候位（站在旁边等），释放后按"先到/关系/心情"决定；败者表情+台词；玩家可以故意制造争抢。
实现：`world.ts` 新增 `waitingFor` 与候位点；`seatAvailable`（`world.ts:73`）与 intent 校验扩展；渲染用现有 walk/idle。
成本：M–L，无美术。
风险：存档校验加严（`validateWorld` 需接受候位态）；7 人时路径互相阻挡，需要放弃/重试策略。

**T2.7 ★ 事件链与小剧场**
卖点：傍晚收工 → 大家涌向书桌排队 → 候位者围观涨好感 → 开饭事件把人群带到餐桌，一条可读的日常。
玩法：world 内有界事件 `{id,phase,until,actors}`，由 tick 触发；邻近角色响应；卡片底部滚动"今日小剧场"。
实现：`src/content/events.ts` + `world.ts` 事件状态机（<2KB 存档）；复用现有行为。
成本：M，无美术。
风险：与自主决策的优先级要明确；事件结束后必须能安全回落到自主状态。

**T2.8 双人同桌小对话**
卖点：两人同桌吃饭时冒出交替气泡，像在看迷你番剧。
玩法：同一家具/相邻位置的两角色触发一次性配对台词（预写表，按关系选）。
实现：事件系统 + 台词池；无需新动画。
成本：S–M（内容为主），无美术。
风险：`facing` 未渲染且纸娃娃保持原朝向（`mirror:'never'`），不能做面对面拥抱/击掌类骨骼动作。

### T3 「有所求的小院」——目标、成长与收集

**T3.1 ★ 需求与心情（极简）**
卖点：角色会饿、会累、会心情不好，行为有了"原因"，玩家能看懂并干预。
玩法：`energy`/`mood` 两个 0–100 整数，随活动与时段线性变化；影响选座权重、速度、表情；过低时出现"闹脾气"台词并优先休息。
实现：world schema 4（Actor +2 个整数）；默认迁移；**不耗 RNG**。
成本：S–M，无美术。
风险：数值平衡；不要引入"失败惩罚"，保持放松定位。

**T3.2 ★ 每日委托**
卖点：给玩家 3 件"今天可以做的小事"，完成后有回报，形成打开理由。
玩法：模板如"让 Claude 完成 3 次工作""安排一次同桌吃饭""让某人排队等 30 秒"；完成后给"小院点数"，可解锁台词/称号/装饰。
实现：`src/content/quests.ts` + world 内计数/完成位（有界）；点名角色用现有 roster。
成本：M，无美术。
风险：判定必须离线、可复现；每日重置用 ticks；旧档兼容。

**T3.3 ★ 成就与图鉴**
卖点：角色档案卡（性格/喜好/口头禅）+ 活动图鉴（第一次吃饭、第一次排队、第一次围观……），满足收集欲。
玩法：卡片内 tab；解锁条件由事件/计数驱动；未解锁显示剪影。
实现：`src/content/achievements.ts` + meta 文件（**不进 world**）；角色头像可直接用 Host 资源 URL（`/api/nidofy-ai-village/assets/claude/parts/face-happy.png`，同源 `<img>`），零新美术。
成本：M，无美术。
风险：条件不可作弊也不可因旧档丢失；文案双语。

**T3.4 收集品与装饰解锁**
卖点：小院逐渐"变满"，有可展示的收藏墙。
玩法：委托/成就奖励解锁摆件（灯笼、风铃、盆栽），可在摆放模式放置（衔接 T4.2）。
实现：装饰走布局数据 + 程序化或复用贴图；收集状态进 meta。
成本：M–L，低–中美术。
风险：与家具摆放/场景迁移耦合，依赖 T4.2 先行。

**T3.5 ★ 小院日报**
卖点：每次打开先看到"今天的小院"：谁工作最多、谁吃最多、发生了什么事件、关系变化。
玩法：本地生成一段 3–6 行文本，卡片顶部或 tab 展示；可按天回看 7 天。
实现：`src/content/report.ts` + 有界日志（最近 7 天摘要 <4KiB，写入 world 或独立 meta）。
成本：M，无美术。
风险：64KiB 容量；跨天/时区；不得读会话内容。

**T3.6 连续在场与问候**
卖点：连续第 N 天打开，角色会说出不同问候；轻量留存机制且不惩罚断签。
玩法：记录最近打开日期与连续天数；问候台词随天数/关系变化。
实现：meta 文件；打开时判定。
成本：S，无美术。
风险：改系统时间会误判；不做惩罚性设计。

### T4 「我的小院」——交互与自定义

**T4.1 ★ 点击派活**
卖点：点角色→选"去工作/去吃饭/去休息/去找 TA"，玩家从旁观者变成小院管理员。
玩法：选中角色后点家具/角色下发指令；心情低时角色可能"不情愿"（先做个表情再执行），增加趣味。
实现：`controller.ts` 新增 tap/hotspot 派发与新协议消息；world 直接设置目标 intent（复用现有 approach/use 状态机）。
成本：M，无美术。
风险：与自主决策的优先级；非法目标返回明确反馈；不能破坏家具独占。

**T4.2 家具摆放 / 装修编辑器**
卖点：拖动家具改变布局，小院真正属于玩家；与收集/装饰形成经营闭环。
玩法：摆放模式中拖动 3 件家具与装饰，保存为布局；校验可行走、不重叠、留出通道；可切换预设"模板"。
实现：world schema 4/5 存布局（每件 <16B），`world.ts` 的 obstacles/hotspots 由基础场景 + 布局派生；`scene.ts` 家具绘制改为按布局每帧生成；**`sceneVersion` 不再严格绑定**（迁移表）。
成本：L，低美术（复用现有家具贴图）。
风险：这是**最高价值的系统级玩法**，也是最大改动：寻路、校验、渲染、存档、旧档迁移全要改；建议在 v0.6 单独验收。

**T4.3 相机缩放 / 聚焦**
卖点：滚轮放大看角色表情，双击角色镜头跟随，截图更好看。
玩法：缩放上限约 1.6×（背景原图 1086×1448 在 340px@DPR2 下约 1.6× 清晰余量），拖拽平移，双击复位。
实现：`frame/viewport.ts` + `scene.ts` 的 `layout/local` 反变换；`viewport.spec` 的"全可见"断言需同步修改。
成本：M，无美术。
风险：与拖拽/气泡坐标联动；缩放后命中检测必须一致。

**T4.4 ★ 拍照 / 明信片导出**
卖点：一键保存当前画面为带日期与小院名的明信片，分享欲 + 纪念感。
玩法：按钮 → frame `extract` 出 PNG → 父页加边框/日期 → 下载文件。
实现：新消息 `postcard{bytes,w,h}`（≤4MB）；父页 objectURL 下载；sandbox 无 downloads 权限，必须父页保存。
成本：M，低美术（可选 1 张边框）。
风险：WebGL `extract` 兼容与耗时；64KiB 响应上限不能走 Host；本地文件而非网络分享。

**T4.5 键盘与无障碍**
卖点：Tab 选人、方向键示意、Esc 取消，读屏也能听到状态变化。
玩法：完整键盘等价操作 + `aria-live` 状态播报。
实现：父页 UI + frame 焦点管理；文案收口到 `messages.ts`。
成本：S，无美术。
风险：不能干扰主对话 IME/快捷键；Esc 只在自身作用域消费。

**T4.6 窄屏与迷你卡**
卖点：窗口 <764px 时不再直接隐藏，而是收成底部迷你卡/抽屉。
玩法：显示当前时间、最多 3 个在活动的角色与一句日报；点开展开。
实现：`floating-layout.ts:20-22` 增加 fallback 几何；不遮输入框。
成本：M，无美术。
风险：依赖官方 DOM 标记，需要随 DSH 版本复验。

### T5 「更大的小院」——内容与美术扩展

> 这一组的共同前提是 **T7.1 资源惰性化**：目前所有纹理在连接时全量拉取、常驻内存、iframe 重挂全量复制，新增内容会线性推高包体/内存。

**T5.1 ★ 新家具与新活动（优先复用现有动作）**
卖点：书柜（看书）、花盆（浇花）、猫窝、鱼缸、茶桌（两人对坐），小院内容立刻翻倍。
玩法：新 hotspot 复用 work/eat 的手臂贴图做成"看书=工作姿态""浇花=吃饭手势"，先零新动画落地，之后补专属动作。
实现：`scene.json` 家具 + `<asset>-back/-front.png` 两片 + manifest + resources 重生成；同时修掉三处硬编码：z=3080、饭碗单例坐标、"有人吃饭才隐藏饭碗"（`frame/scene.ts:88,120,159`）改为按家具 rect/props 计算。
成本：M（每件 2 张纹理、0.3–2MB 解码），低美术。
风险：**新增家具会改变 `sceneVersion`，旧档会被拒**；必须先做场景迁移方案（见 T7.4）；21 组互动 QA 需扩容。

**T5.2 第 5 种表情（害羞/生气/难过）**
卖点：情绪层次提升，争座、被摸头、完成委托时更生动。
玩法：新增 1 种表达，接入对话与事件。
实现：`art/types.ts` 的 `Expression` 联合 + 7 份 `character.json` + 7 张脸 PNG + manifest/resources。
成本：M，中美术（≈+2.1MB 解码，7 张图）。
风险：必须与原脸型配准；一次只加 1 种，分版本验收。

**T5.3 换装 / 配饰**
卖点：节日围巾、生日帽、季节小配饰，丰富但不改骨架。
玩法：每个角色 1–2 件配饰，可在卡内切换；节日自动换。
实现：复用纸娃娃部件系统（`paper-doll.ts`），world 存 outfit id。
成本：M，中美术（7 张/套）。
风险：`mirror:'never'` 与不对称配饰需逐件审查；存档字段。

**T5.4 季节皮肤（同几何换皮）**
卖点：春樱/夏祭/秋叶/冬雪/夜灯，同一世界不同气质。
玩法：只替换背景与家具贴图版本，不改变热点几何与行为。
实现：scene 增 skin 映射；每套 1 背景（≈2.2MB raw）+2–4 小装饰；依赖 T7.1 惰性加载。
成本：M–L（美术为主），中美术。
风险：全量预载会 +6–25MB 解码并逼近 160 张上限；建议只装当前皮肤。

**T5.5 新场景（书房/水族箱/天台）**
卖点：内容量最大的一步，甚至可作为付费/主题内容包。
玩法：切换场景改变背景、家具、热点与活动组合，小院有"换地方生活"的新鲜感。
实现：world 增 `sceneId`，场景注册表，SaveStore 按场景校验，definitions/frame 多场景 init，资源脚本泛化，切换 UI。
成本：L，高美术（每场景 +10–15 纹理、+6–14MB 解码）。
风险：资源协议、存档迁移、旧档兼容、测试矩阵全部翻倍，应单独立项。

**T5.6 访客 / 第 8 位角色**
卖点：节日限定访客或新伙伴，直接拉高话题度。
玩法：临时访客到访 1–2 天，与居民互动、留下礼物。
实现：`roster.ts` 白名单扩展 + 新角色 16 PNG（≈2–3MB）+ 角色定义/动画 + 存档角色位。
成本：L，高美术。
风险：旧版会拒读新角色存档；访客若"不落盘"会与可见状态不一致，不建议做影子访客。

**T5.7 节日迷你游戏**
卖点：节日限定的 1–2 分钟小游戏（找灯笼、点亮烟花、翻牌认角色），给奖励与谈资。
玩法：用现有表情贴图 + DOM 实现，不影响主世界；结束后角色给出反应。
实现：父页新浮层 + 简单状态机；奖励写 meta。
成本：M，低美术。
风险：偏离"陪伴/观赏"定位，建议节日限定、默认不打扰。

### T6 「与你同频」——DSH 深度联动（旗舰差异化）

> 这是发行记录里明确未做的"真实 Agent 状态映射"（`notebook-village-2026-10-21.md:53`），也是"AI 小院"名实相符、把 DSH 使用时长转化为游戏时长的关键。约束：只读、不复制 Agent Loop、不写会话、异常不影响执行。

**T6.1 ★ Agent 状态映射（最小版，零 Host 改动）**
卖点：你在让 AI 干活时，小院里对应角色也在写写画画；等审批时它们聚到桌边等；完成时全员冒心庆祝。
玩法：`running → 工作`、`pendingInteraction → 等待/围观`、`completionUnread → 庆祝`、`error → 沮丧`；冷恢复不重放一次性反应。
实现：浮卡 Surface 的 standardProps 自带 `useSessionStatus`（Live2D 已有先例 `packages/live2d/src/client/index.ts:44-46`）；父页向 frame 发 `pulse{kind}` 表现消息，**Host 零改动、不落盘**。
成本：S，无美术。
风险：误读 completed/error；多会话时聚合规则；不要做成"必须打开聊天页才算"。

**T6.2 真实会话/Agent 投影（Host 版）**
卖点：多个会话同时进行时，小院能反映"全局工作状态"，甚至不同角色对应不同模型/会话。
玩法：投影为粗枚举（空闲/运行/等待审批/刚完成/出错）+ 计数，经现有 4s 心跳回包或轻量 GET 下发。
实现：`src/index.ts` inject `sessions`/`agents`/`sessionQuery`，`ctx.on('session/event')` / `agent/status` 只做只读投影（desktop-pets 已有同型先例 `packages/desktop-pets/src/index.ts:14`、`src/pets.ts:15`）；只落枚举与计数，**不读对话文本、不落文本**。
成本：M，无美术。
风险：官方 API 暴露面需核实；隐私与异常隔离；DSH 升级需复验。

**T6.3 完成庆祝与应用内通知**
卖点：任务完成/需要审批时，小院有一次庆祝或举牌提醒，可当作轻量通知。
玩法：`turn/end` → 气泡 + 粒子 + 可选提示音；未读徽标；toast 与卡片内提示合并防疲劳。
实现：父页新 `shell.overlay` toast 条目 + 表现消息；原生通知需 Electron 载体（不在纯插件范围）。
成本：S–M，无美术。
风险：打扰频率；多会话聚合；页面 focus 状态。

**T6.4 会话/项目轻联动**
卖点：小院公告板展示"当前项目/最近提交/笔记数量"等只读信息，与 Git、Notebook 形成工作台氛围。
玩法：Git 展开时角色让位并"收拾桌子"；Notebook 提交笔记时角色递本子。
实现：优先只用公开布局标记（`floating-layout.ts`）与 `nidofy:floating-panel-open` 事件；跨包实时联动需在 `plugin-shared` 定义最小公开事件，**不要调用私有 API**。
成本：M–L，无美术。
风险：跨包契约与版本矩阵；Notebook 目前只有私有 window 事件。

**T6.5 与桌宠联动（可选安装）**
卖点：小院角色与桌面悬浮桌宠共享状态/形象，一个在桌面、一个在卡片里。
玩法：可选：同一角色同时出现在两处，忙碌状态同步。
实现：需跨包契约（desktop-pets 的 Electron 载体与公开事件），或先做"同一角色形象"的弱联动。
成本：L，跨包。
风险：两插件独立安装原则；不能引入硬依赖。

**T6.6 声音（建议后期）**
卖点：完成音、点击音、昼夜环境音，情绪反馈最直接。
玩法：默认静音，用户显式开启；音量设置。
实现：Host 白名单扩展 audio MIME + 父页 WebAudio；CSP 需加 `media-src`；资源生成脚本与许可证。
成本：M，低–中美术（音频素材）。
风险：自动播放需手势；包体与授权；与"隐藏即停"生命周期一致；建议 v1.0 再做。

### T7 系统与品质（支撑性）

**T7.1 ★ 资源惰性化协议（其他美术扩展的前置）**
问题：130 张纹理在连接时全量拉取并常驻（`runtime.ts:97-113`、`frame-bridge.ts:22-24`），Host 也整包驻内存（`service.ts:65-69`），iframe 重挂全量复制。
方案：frame 协议 v2——按场景/角色增量下发 assets、允许释放不再使用的纹理；`scene.ts` 已有清理基础（`dispose`）。
成本：M，无美术。
收益：解除 160 张/66MB 常驻限制，为多场景、皮肤、换装铺路。

**T7.2 设置与偏好（独立文件）**
卖点：音量、画质、动画频率、字号、语言、暂停规则、角色管理。
实现：官方 `settings.section`（source-control 先例）或卡内 tab；偏好写入 `<profile>/nidofy-ai-village/settings.json`（独立 schema/revision/原子写），**不进 world**；不要用官方 Config 服务（提交会触发 Host 重开与 epoch 变化）。
成本：S–M，无美术。

**T7.3 统计与周报**
卖点：累计工作时间、吃饭次数、同处时长、连续打开天数，生成"小院周报"。
实现：客户端聚合 → meta 文件；本地生成文本；不读会话内容。
成本：S–M，无美术。

**T7.4 ★ 存档迁移与诊断**
问题：`validateWorld` 只认 1/2/3，`sceneVersion` 严格相等（`world.ts:199`）；新格式旧客户端显式失败。
方案：world v4 设计先行（新增字段全部给默认、环形日志有界、64KiB 预算测试）；新增只读诊断（列出 current/previous/恢复链/32 快照、显式选版恢复）。
成本：M，无美术。
风险：不得绕过锁/CAS/保护名单；第二进程占锁时 Host 目前直接抛错导致插件加载失败，应降级为"占用只读"。

**T7.5 文案与 i18n 收口**
问题：`Floating.tsx:46-58` 里仍有硬编码中英双分支，locale 用 `t('title') === zh.title` 探测。
方案：全部文案进 `messages.ts`；新增内容表统一双语；测试校验 key 完整。
成本：S，无美术。

**T7.6 性能与验收基线**
- 新增逐帧 JS ≤1ms（现 0.35ms 均值）；纹理新增 ≤30 张/解码 ≤25MB；不得让 frame 自起 rAF/ticker。
- 每次新增玩法补：纯逻辑确定性测试、schema 迁移/冷恢复等价、64KiB 上限、浏览器夹具交互、双模式、repeat enable/disable、无外网/pageerror、性能采样。
- 真实 Desktop 验收仍按既有门槛（隔离 profile、CDP 18751、完整重启），0.3.2 尚未复验。

## 4. 组合示例："一个理想的小院晚上"

以下全部由 **T1–T3 的无美术功能**组合而成，用来验证"内容密度"是否足够：

1. 21:10 打开小院（右侧卡片）。顶部显示 `21:10 · 秋 · 阴`，底部日报："今天 Claude 工作了 5 次，Gemini 在坐垫睡了 2 小时，两人在傍晚同桌吃过饭。"
2. 今天是中秋，场景里有灯笼，20:00 触发"赏月"事件：三位居民聚到空地，头顶冒 `♪` 与烟花粒子（T1.4/T1.5）。
3. 21:30 系统事件"收工"：三人同时走向书桌，两人排队候位，一人围观（T2.4/T2.6/T2.7）；玩家点了一下排队的 Grok，它冒 `?` 并说"今天写得够多了吧？"（T2.1/T2.3）。
4. 玩家把千问拖到"找 Claude"的位置，触发双人小对话（T2.8）；关系 +1。
5. 打开"今日委托"：让 Claude 连续工作 2 次（已完成 1/2），做完给 10 小院点数（T3.2）。
6. 关掉浮卡（世界暂停）。第二天 20:00 再打开，日报回顾昨天，关系图显示 Claude 与千问更亲近，成就"第一次围观"解锁（T3.3）。

## 7. 不建议做 / 需单独立项

| 方向 | 原因 |
| --- | --- |
| 在线多人、社区、云存档 | 单 profile 单世界 + 跨进程独占锁 + 无服务端推送；纯插件做不了 |
| LLM 实时对话 | 无模型 API、CSP 禁网；如要做需明确成本/隐私/延迟/内容安全，且与"离线预写台词"是两条产品路线 |
| 复杂骨骼/转身/拥抱击掌 | 正面纸娃娃、`mirror:'never'`、无侧面/背面图；改动等于重做美术 |
| 壁纸级高清导出 | 角色原生脸约 290px、显示 108 高；1920 宽 ≈5.3× 会糊；与 4MP 上限、8MiB/文件、离线体积冲突 |
| 原生桌面通知 | 需 Electron 载体适配，不属于纯插件能力 |
| 音频（首版） | 需改 CSP/media、白名单、授权与包体；建议 v1.0 且默认静音 |
| 通用资产市场、换装商店 | 离线包 + 无服务端 + 固定美术管线；会引入授权与安全面 |

## 9. 测试与验收清单（新增玩法必补）

- 纯逻辑：`tests/autonomy.spec.ts`（确定性、tick 快照）、`tests/multiplayer.spec.ts`（多人/家具独占）、`tests/roster.spec.ts`（世界 round-trip）、`tests/retention.spec.ts`（快照）。

- 浏览器：`scripts/ai-village-phase4.mjs check` 的夹具交互（点击、气泡、排队、事件链、委托、设置）+ 七人/50 次侧栏/重连/重载回归。
- 生命周期：重复启停不累积监听/纹理/定时器；隐藏即停；断连/冲突暂停不重置。

- 性能：新增逐帧 JS、纹理数/解码内存、可见 FPS、隐藏 CPU；与现有 0.35ms/130 张基线对比。
- 双模式：DSH 浮卡与 `standalone` 开发页都要过。

## 附：一句话结论

**小院已经有了一副很好的骨架和 7 位可爱的居民，下一步最缺的不是更多像素，而是"时间、语言、目标、关系，以及与你的 AI 工作的关联"。优先做 v0.4 的可读性与 v0.5 的社交/目标层，用现有资产验证玩法；家具摆放、新表情、季节与新场景放在资源惰性化之后；Agent 状态映射作为 v1.0 的旗舰差异化。**

## 0. 结论摘要

1. **UI-v1 是一次成功的结构升级，不是需要推倒重来的设计。** 它把小院从 0.6.1 的"标题 + 表单 + 画布 + 常驻内容区"改成了"同一游戏视口 + 悬浮 HUD + 四入口可收起管理层 + 明确的布置/拍照模式"，场景面积、沉浸感和操作路径都明显改善。方向应当保留，工作是**把气质和状态补完整**，而不是再换一次壳。
2. **当前视觉可以概括为"暖纸 + 森林绿轻玻璃 + 绘本小院"**：奶油纸面板（规范定义亮色 90–96% 半透明 + blur；**本次证据因软件渲染全部回退为实色** `#FFFCF5`/`#28352E`）、墨绿文字（`#34473C`）、森林绿强调（`#456740`）、赭金焦点（`#946A20`），叠加在暖沙/蜜木/鼠尾草色、软绘无描边的绘本庭院上；再配自制 20px/1.7 线宽 SVG 与 44px 完整纸娃娃头像。低饱和、低刺激、克制，这是它最好的部分。
3. **最大的三个视觉问题不是"不好看"，而是"两层皮"和"没闭环"**：
   - **场景与界面两套光**：暮色环境是全局冷灰乘算（背景 ×`0x9EACCD`、角色 ×`0xD2DCF0`，仅两个固定暖斑），暖纸 UI 盖在冷灰画面上出现冷暖断崖；暗色主题则是"墨绿框包住暖亮白昼画"，像灯箱。
   - **新家具与绘画背景两种画法**：0.5/0.6 新增的长椅、书架、风铃、纸灯笼、花叶挂饰是代码矢量平涂，和 AI 绘画的书桌/餐桌并置像占位件。
   - **状态与层级没闭环**：没有 hover/pressed/success/disabled 的完整视觉；规范写的 140–180ms 动效实际没有实现；主操作按钮只有"保存布置"有强调；浏览器原生滑杆/复选框还是默认蓝。
4. **视觉语言的"名字与规则"还缺位。** 冻结规范只有第 4 节 token/排版/图标，没有视觉概念、情绪板、材质/光照、动效性格、图片处理与文案语调；`ui-contract.json` 仍标 `DESIGN_NOT_IMPLEMENTED`、基线停在 0.6.1；布局标定稿 HTML 未进仓库且 NOT RUN。也就是说：**冻结的是信息架构与参数，不是气质。** 下一版最值得做的，是把气质变成可继承、可验证的规则。
5. **宿主适配是当前最明显的"插件感"来源**：主题默认"跟随系统"（OS），不跟随 DSH 宿主主题；深色 DSH 里默认出现浅色小院卡片。对照 `source-control`、`live2d` 都已读宿主 `--dsw-alias-*` 与 `color-scheme:inherit`，小院只读了 `--dsw-font-family`。
6. **窄卡与短高是信息密度与构图问题，不是尺寸问题**：340×720 半开抽屉内容区约 249px，首屏塞进"在场 + 管理 + 8 个日常互动 + 配饰 + 共同经历"；抽屉上缘（48% 高）从场景中部横切，主角只剩头部/上半身；320×360 深抽屉占 77%、几乎盖住世界，按钮被抽屉下缘截断。冻结预览里"一个 CTA（查看日常互动）"的呼吸感在实现里被 8 个动作按钮替代了。
7. **建议的 v1.1 主线（按优先级）**：① 设计系统收口（状态色/动效/主次按钮/token 单一来源）；② 场景光照统一（重做暮色、家具插画化、角色与地面分离）；③ 窄卡密度分级 + 宿主主题桥接；④ 内容页面的"绘本编辑感"（手账/相册/日报/心愿印章）。
8. **三个可选风格路线**：
   - **A「暖纸画框」（推荐）**：UI 是立体绘本的纸标签/书签/窗台，场景是唯一画面主角，克制、可长期扩展。
   - **B「轻仪表盘」**：强化四入口的管理效率，信息密度更高、组件更系统性，代价是与绘本气质渐远。
   - **C「双主题联动」**：界面明暗与环境午后/暮色联动，暗色即暮色灯火，整体感最强，但违背当前"环境不影响主题"的冻结条款，需要产品决策。
   推荐 **A 为主线 + C 作为可选开关**，B 只用于宽屏 inspector 的信息组织。
9. **明确不建议**：全屏毛玻璃/大范围实时模糊、重画七位角色、3D/物理、全屏 bloom/景深、用天气粒子去补氛围、暗色模式直接把场景压成夜景（除非走 C 路线）、外链字体/图标库。
10. **验收前提**：视觉冻结若要成立，需要补 GPU 下的玻璃材质（现全部是实色回退）、320/340 英文、800×600 与宿主 800×440、560/900 断点、暗色次级状态、键盘巡检、宿主主题、真实 Windows/GPU 与人工观感（G01–G05）证据；目前的 23 张截图覆盖了主路径，但没有覆盖边界组合，且不是当前 HEAD 的干净树重拍。

## 1. 视觉方向定位：它现在是什么风格

### 1.1 三层视觉

| 层 | 现状 | 视觉作用 |
| --- | --- | --- |
| 场景（iframe 内） | 1086×1448 AI 软绘背景，无描边、强方向光、斑驳树影；360×480 逻辑世界；角色 108 逻辑像素、赛璐璐软阴影 + 深色描边；地面椭圆软影 | 提供情绪与叙事主体，是"小院"；也决定了 UI 必须是它的画框 |
| 界面（父页 DOM） | 奶油纸 90–96% 不透明 + `backdrop-filter: blur(8/12)`（**证据为软件渲染实色回退，玻璃未呈现**）；12/16/20 圆角；1px 低对比描边（line vs solid 仅约 1.45:1/1.98:1）；暖纸底 `#EAE3CF` + 大阴影 `0 12px 50px #14291930`；四入口 Dock、抽屉、右侧 inspector | 承担导航与操作；目前是"贴"在画上的悬浮玻璃纸 |
| 图形与文字 | 自制 15 个内联 SVG（20×20/1.7 圆端点）；正文 14/1.5、辅助 12、标题 18/1.35；正文用宿主 `--dsw-font-family`、标题硬编码 system-ui；44px 纸娃娃合成头像、六张家具缩略图 | 决定"精致感"；目前功能性足够，性格与状态不足 |

### 1.3 设计语言画像（判断）

- **不是拟物，也不是扁平系统 UI**，而是"柔光绘本 + 轻玻璃纸片"：材质只做到 90–96% 不透明 + 小面积 blur + 1px 线，刻意避免重毛玻璃。
- **色彩有明确的主角**：暖沙/奶油/蜜木/鼠尾草（场景与纸面同族，色相 32–60°），森林绿做强调，藏青只属于角色（唯一冷色焦点）。这套关系成立，比大多数插件自建 UI 更协调。
- **低刺激、低信息密度**的设计意图（图标+文字的四入口、单列分组设置）适合"陪伴/观赏"定位；但和"丰富的游戏内容（8 活动、6 心愿、12 记忆、3 布局、20 张相册）"之间还没找到视觉上的密度语言。
- **最像"产品"的部分**：照片模式（离屏 720×960、纸边、日期、相册限额、删除确认）与布置模式的受控锚点（78% ghost、合法/非法、撤销/保存）。它们有明确的"对象—反馈—确认"链条，视觉与语义一致。
- **最不像"产品"的部分**：动效、hover、空状态、成功回执、主操作层级——这些细节缺失让冻结的"沉浸式"停留在静态截图里。

### 1.4 与宿主和兄弟插件的关系

- 小院是仓库里**唯一自建完整插画 + 设计系统**的插件；`source-control`、`live2d`、`desktop-pets` 都走宿主 token 或原生窗口。小院自管 10 个颜色变量、只复用 `--dsw-font-family`。
- 结果是并排时的"系统框 vs 手办盒"：Git 卡片 340 宽、16 圆角、宿主灰黑；小院 340 宽、20 圆角、暖纸自绘阴影。两者不冲突，但**不像同一套产品**。
- 同一角色在三个插件里是三种画风（Live2D 修长立绘、桌宠润泽精灵、小院 2 头身赛璐璐）。这是产品级一致性议题，不是单个插件的 bug。

| 缺口 | 事实 | 影响 |
| --- | --- | --- |

| frame 主题 | frame 的 view 载荷没有 theme；气泡/ghost/锚点色在 `scene.ts` 里硬编码为亮色 | 暗色主题下场景内组件仍是亮色，形成第二套主题 |

## 3. 布局与信息架构

### 3.1 常态结构

```text
┌────────────────────────────────────────────┐
│ [消息] [第1天·14:00]        [暂停][更多]    │ ← HUD 悬浮，无标题底板
│                                            │
│              360×480 小院世界                 │ ← iframe 填满，氛围延展铺边
│                                            │
│ [居民] [心愿] [布置] [手账]                  │ ← Dock 56 高，收起态
└────────────────────────────────────────────┘
       展开：抽屉半开 min(360,0.48H) / 深开 H−84
       ≥900 宽：右侧 inspector 360 + Dock 左下
```

- **四入口固定顺序**：居民 / 心愿 / 布置 / 手账。四个页面模板一致（顶栏 40 + 可滚动内容区 + 底部 Dock），切换时保持展开高度。
- **二级页**：居民（在场/安排入住 → 选中居民 → 日常互动/配饰/共同经历）、心愿（心愿/一起活动）、布置（家具/挂饰/氛围）、手账（回忆/相册）。
- **浮层**：消息面板（左上 320）、更多（窄窗）、视角、居民轻卡（220，按角色世界坐标投影）、设置（360 全高）、确认/错误/加载。
- **模式**：布置（Dock 换成 170/110 托盘）、拍照（HUD/Dock 隐藏，仅留退出/取景/拍摄）。

### 3.2 响应式形态

| 条件 | 实现 | 视觉评价 |
| --- | --- | --- |
| W<320 或 H<360 | 暂停 + 说明卡 | 仍渲染 HUD，可能和错误卡叠在 top:72；没有"调整显示"入口 |
| 320≤W<560 | 紧凑 HUD（消息/时间/暂停/更多）+ 底部抽屉 | 340×720 主形态；半开抽屉内容区约 249px，首屏偏挤 |
| 560≤W<900 | 全 HUD（暂停+拍照+视角+展开+设置+关闭）+ 抽屉居中 | 580×720 英文形；空间舒展，Dock 与场景比例最好 |
| W≥900 | 右侧 inspector 360 + Dock 左下（宽 352） | 1080×760 形态；inspector 覆盖世界右缘约 105px，构图略偏 |
| 360≤H<480 | 抽屉打开即深开、隐藏次要说明、折叠选择器 | 340×480 世界几乎全屏（上下仅约 13px 带），是最干净的一档；320×360 深抽屉占 77%、场景仅剩约 84px，chip 被 Dock 横切，是四档中最不优雅的 |
| 宿主 | 普通态占右侧 340 + 留白 364；展开态占对话列 ≤1080×760 并避开 composer | 展开态视觉最完整；普通态是"右栏卡片"，与 Git 上下叠放 |

### 3.3 布局层面的具体问题

1. **inspector 覆盖世界**：1080 宽时世界 570 宽居中（x 255–825），inspector 从 720 开始，覆盖世界右侧约 105px（18%）。冻结规范明确"抽屉是覆盖层、不改变投影"，因此这是设计选择；视觉上角色/家具可能被面板压住，"看看"动作会收起面板缓解。若后续追求构图，可考虑"打开 inspector 时世界向可见区中心平移"（需产品决策）。
2. **窄卡首屏密度**：340 宽半开抽屉内容区 = 345−56−40 ≈ 249px；当前首屏包含 44px 头像行 + 8 个动作按钮 + 配饰 + 共同经历标题，实际需要滚动。冻结预览 `DESIGN_340x720_light_residents.png` 的首屏是"一个居民 + 一个 CTA + 一行说明"，更克制。
3. **短高**：320×360 抽屉全开占 H−84=276，面板 180px；画面只剩顶部一条。冻结规范允许"短高打开即深开"，但视觉上应保留一点世界的"呼吸"，并让可滚动区域有下缘渐隐。
4. **resize 跨 480 不重算**：已在半开状态的抽屉在高 480 附近往返时不会切换半开/全开，可能出现 174px 总高、134px 面板的不可用中间态。
5. **toast 位置偏差**：全开抽屉时 `bottom=calc(100% - 72px)`，比规范"抽屉上缘 +12"低 12px；视觉上会压住面板内容一点。
6. **CSS 层叠事故**：`.village-card article{padding:0}` 覆盖 `.village-journal/.village-status` 的内边距；`.village-card nav{padding:0}` 覆盖 `.village-tabs` 的 3px 内缩。结果是回忆条目距左侧 2px 描边仅 2px、状态卡贴边、Dock 的内缩失效（1080 album 截图可验证）。这是低成本、高可见度的修复。
7. **半开抽屉切角色**：340/580 的半开抽屉总高 48%H（720 高时 345px），上缘从场景中部横切，主角只剩头部/上半身（residents/wishes/decor/journal、580 en-journal 均可复现）。这是构图问题，不是信息问题：需要调抽屉系数/起点，或让默认镜头在抽屉展开时轻微上移。
8. **图标语义撞车**：抽屉头"深展开"与 HUD"展开小院"共用同一个斜向双箭头图标，在 1080 inspector 同屏可见；消息（铃铛）与冻结预览（气泡）、心愿（星）与预览（心形）、设置（滑杆）与预览（齿轮）也存在漂移。需要一个图标语义表统一裁决。
9. **七人入住页布局**：7 个原生蓝色复选框排 2 列，"全员入住"插在右列第 4 行、"仅留当前"在左列第 5 行，两个批量操作被拆散在网格里；应移到列表底部作为一组次级操作。

## 4. 逐页视觉评审

> 截图均在 `packages/ai-village/art/QA/ui-v1/visual/`；`metadata.json` 记录了 CSS 尺寸、DPR、主题、语言与状态。

### 4.1 默认态（浏览）

- **340×720 亮色（[图](../../packages/ai-village/art/QA/ui-v1/visual/340x720-light-zh-default.png)）**：上下暖雾延伸带 + 居中 340×453 世界；HUD 两枚纸签（消息/时间）+ 右侧暂停/更多；底部四入口 Dock。主画面干净，角色是唯一视觉焦点。这是整个改版最成功的一帧。

- **580×720 英文（[图](../../packages/ai-village/art/QA/ui-v1/visual/580x720-en-default.png)）**：全 HUD 六项、Dock 居中、英文标签无截断，是最舒展的常规形态。
- **1080×760 亮/暗（[图](../../packages/ai-village/art/QA/ui-v1/visual/1080x760-light-default.png)、[图](../../packages/ai-village/art/QA/ui-v1/visual/1080x760-dark-inspector.png)）**：场景放大到 570×760，左右大面积氛围延展；宽屏 inspector 与左下 Dock 让"游戏 + 管理"并存。亮色版氛围带与场景衔接自然；暗色版 inspector 很深，世界很亮，对比强。

### 4.2 居民（[图](../../packages/ai-village/art/QA/ui-v1/visual/340x720-residents.png)）

- 完整体：44px 纸娃娃头像 + 名称/状态 + "看看"；选中后内联 8 个日常互动 + 配饰 + 共同经历。
- 优点：头像质量明显优于旧的单脸 PNG；"看看"的位置固定，符合"先看人再做事"的心理顺序。
- 问题：半开首屏过密（见 3.3）：首屏可见约 6 个互动 chip，其余与"共同经历"需要滚动；8 个动作按钮与"安排入住"、二级 tab 全部同款描边，层级靠位置而非样式；"共同经历"视觉存在感弱（纯文本列表），不像"关系"。
- 七人模式：7 个**原生蓝色**复选框排 2 列，"全员入住"与"仅留当前"被拆散插在网格中（右列第 4 行 / 左列第 5 行），批量操作没有成组。
- 冻结预览的对照：预览是"一行居民 + 一行说明 + 查看日常互动 CTA"，实现选择了更直接的 8 宫格。两者都可辩护，但**在 320/340 窄卡上，预览的密度更成立**。

### 4.3 心愿（[图](../../packages/ai-village/art/QA/ui-v1/visual/340x720-wishes.png)）

- 现状：二级"心愿/一起活动"分段 + 三条 `○ 标题` + "去看看"。
- 问题：这是全 UI 最"表单"的页面：没有完成态视觉（只有字符 ○/✓）、没有奖励/装饰的视觉悬念、没有插图；分段控件与操作按钮同款。密度也偏低：每条约 90px，340 首屏只显示约 2.5 条，六个"去看看"重复出现。心愿是"目标感"的核心页面，却几乎没有情绪设计。
- 建议：愿望卡（印章式完成态、未解锁剪影、对应装饰小图标、单主操作），"已完成"用盖章/纸签而非勾字符。

### 4.4 布置（[图](../../packages/ai-village/art/QA/ui-v1/visual/340x720-decor.png)、[合法拖放](../../packages/ai-village/art/QA/ui-v1/visual/340x720-arrange-legal.png)）

- 家具页：三模板（午后小院/阅读角落/花草角落）+ 2 列家具缩略卡（书桌/餐桌/坐垫/双人长椅）+ "开始布置"。缩略图来自正式美术，是最有"内容感"的页面之一。
- 问题：分段 tab（家具/挂饰/氛围）、模板按钮、目录卡片三层都用相近的描边/圆角语言，层级不清；"开始布置"与模板按钮同款，主操作不突出。
- 布置模式：锚点环、78% ghost、顶部 toast"可放置·松开选择锚点"、绿色托盘（选中家具 + 锚点按钮 + 折叠模板 + 撤销/取消/保存）语义完整，保存是唯一 `.primary` 按钮，是整套 UI 里最"完成"的交互。
- 小问题：托盘里的"选中家具"选择器与锚点按钮偏小；短高（110 托盘）时详情折叠成选择器，空间仍紧。

### 4.5 手账（[图](../../packages/ai-village/art/QA/ui-v1/visual/340x720-journal.png)、[相册宽屏](../../packages/ai-village/art/QA/ui-v1/visual/1080x760-album.png)）

- 回忆：`回忆/相册` 分段 + 空态一句话；有内容时是左侧 2px 绿色描边的时间线段落。
- 问题：空态太素，缺少"第一段回忆会在这里发生"的引导；有内容时因 `article{padding:0}` 叠加，文字几乎贴住描边。
- 相册：宽屏 inspector 内显示"本地相册 1/20"、上限说明、条目标题与查看/导出/删除，但**证据截图里没有出现缩略图**（`AlbumImage` 是异步 blob，lazy 加载；可能是截图时序问题，也可能是真实显示缺口）。相册的"拍立得/剪贴簿"想象没有落地：没有相纸白边、没有日期角标、没有网格。
- 建议：相册改为 2 列拍立得卡（白边 + 手写日期 + 点击预览），宽屏 3 列；回忆页做时间轴/贴纸语言；空态用现有纸娃娃素材合成小插画（零新绘画）。

### 4.6 消息（[图](../../packages/ai-village/art/QA/ui-v1/visual/1080x722-notifications-populated.png)）

- 现状：左上 320 面板，标题"消息" + "全部已读"；条目"• 标题 + 参与者/发现物"；底部"查看手账"；铃铛带 9+ 角标。
- 优点：信息真实（来自已确认的首次事实），文案有叙事性（"一起照料""给绿叶一点水""同一页故事"）。
- 问题：条目视觉差异只有文本；"全部已读"是普通按钮，与"查看手账"权重相同；未读圆点很小；没有头像/事件图标；面板与暖纸环境的对比尚可，但缺少"信笺/便条"的材质暗示。

### 4.7 设置（[图](../../packages/ai-village/art/QA/ui-v1/visual/340x720-settings.png)）

- 结构：显示与交互 / 视角与操作 / 运行与存档，单列分组；完成按钮在右上；设置自动提交并显示"设置已确认"。
- 问题最集中：
  - **原生控件未主题化**：复选框是浏览器默认蓝，滑杆（拍照页）也是默认蓝，和奶油/鼠尾草/森林绿完全不搭；`select` 仍显示原生下拉箭头；深色模式下输入框/选择器的对比风险更高（代码没有 `color-scheme`/`accent-color`）。
  - **开发词汇泄漏**：中文界面里出现"暂停原因：user""最近确认修订：r2 · committed"，品牌感与可读性双输；应本地化为"用户暂停""已确认"。
  - 分组标题、条目、说明之间的字号/间距层次偏弱，整页像表单列表，缺少"设置也是一种小院体验"的设计。

### 4.8 拍照（[图](../../packages/ai-village/art/QA/ui-v1/visual/340x720-photo.png)、[宽屏](../../packages/ai-village/art/QA/ui-v1/visual/photo-wide.png)）

- 优点：取景预览是纸边 + 日期的"相纸"，导出 720×960 与三种宿主宽度构图一致；这是最具分享潜力的功能。
- 问题：
  - 三个滑杆是浏览器默认蓝（knob 实测 `#0075FF`、track `#EFEFEF`），日期/边框复选框也是默认蓝；
  - 重置/拍摄/退出三按钮同权重，主操作"拍摄照片"不突出；
  - 相纸白边内框很好，但缺少"AI 小院"署名/地点/更精致的日期排版，作为分享物品牌感弱；
  - 预览/保存/导出是一长串同款按钮，视觉上没有"拍摄 → 调整 → 保存"的流程感。

### 4.9 错误、空态、加载、空间不足

- 错误：`role=alert` + 诊断折叠 + 恢复动作，语义完整；视觉上是统一的纸质卡片，可用。
- 滚动截断与无渐隐：decor 第 4 张卡被 Dock 上缘切半、wishes 第 3 项贴 Dock、320×360 互动 chip 行被 Dock 从中切断、short-arrange-options"生活角落类型"被动作栏硬切、settings"开发与恢复"在面板底被切。规范 3.3 要求"可感知滚动轨迹/下缘渐隐"，实现只有 `scrollbar-width:thin`，截图中不可见。
- 空态：回忆/通知有文案，相册与共同经历没有；空态无插图、无行动引导。
- 加载："正在准备小院…"是一行无容器的文本（`village-loading` 有底但未与整体层级统一），缺少骨架/场景占位。
- 相册加载：`AlbumImage` 加载中返回 `null`，没有骨架或占位；证据里缩略图缺失可能与异步时序有关，必须现场复测。
- 空间不足：暂停说明卡存在，但 HUD 仍渲染，且 insufficient/error 两张卡都定位 top:72，重叠风险；视觉上应只保留解释 + 调整显示 + 关闭。

## 6. 视觉方向建议（v1.1）

### 6.0 先给视觉语言一个名字与五条原则

建议命名 **「暖纸林间 / Paper & Glade」**：小院是一本正在被翻阅的立体绘本，UI 是书页上的纸签、书签与窗台，而不是仪表盘。

1. **场景是主角，UI 是画框**：任何界面元素不得比角色更抢眼；HUD/Dock 永远落在氛围延展区或画面边缘。
2. **暖色统一，冷色让给角色**：纸/木/叶色系共享；冷灰只用于真正的禁用/中性信息；藏青留给角色。
3. **纸质层次替代重玻璃**：面板是纸（细边 + 极轻纹理 + 两层阴影），HUD 是贴纸，抽屉是书页边；不再增加不透明度或 blur。
4. **动效是呼吸，不是装饰**：140–180ms 的淡入/位移，只服务于"出现/选择/完成"，尊重减少动态。
5. **状态用印章/书签表达**：完成=盖章，进行中=书签，未读=角标，不靠大面积色块。

### 6.1 工作线 A：设计系统收口（P0，S–M）

1. **建立视觉概念章节**：情绪词（温暖、安静、被照料）、材质（纸/木/玻璃）、光照（左上暖光）、动效性格（缓入缓出、无弹跳）、文案语调（短句、口语、避免开发词）、图片处理（纸边/日期/印章）。写进 `DESIGN_SPEC.md` 的 §4 之前，成为后续所有视觉决策的依据。
2. **Token v2**：补 hover/pressed/selected/success/warning/ghost/scrim/角标 色；补 spacing scale（4/8/12/16/24）、elevation 两级（卡片/浮层）、motion tokens（140/180ms + `ease-out` + reduced-motion=0）、icon 语义表；把卡片底 `#EAE3CF` 与阴影纳入契约。
3. **单一来源**：把 `ui-contract.ts` 扩展为真正的 token 导出，在 `Floating` 内联为 CSS 变量；删除 CSS 字面量与 floating-layout 的 352/364 硬编码重复；CSS 只注入一次；归档死组件。
4. **表单与原生控件**：`.village-card{color-scheme:light/dark; accent-color:var(--accent)}`；为 input/range/checkbox 写纸质样式（滑杆轨道=线色、滑块=强调色、复选=方形纸签+对勾）；修复暗色下输入框对比。
5. **主次按钮**：定义 `.primary`（强调底）/`.secondary`（描边）/`.ghost`（文字）/`.danger`；应用到拍摄、保存到相册、完成设置、全部已读、邀请同桌、开始布置；布置保存继续保持唯一强 CTA 的位置语义。
6. **动效落地**：抽屉/浮层/设置/照片面板 180ms 淡入+4px 位移；toast 140ms；hover 120ms 背景/描边变化；press 下压 1px；相机恢复 180ms 补间（或 CSS transform 过渡）；全部服从 `data-motion`。
7. **图标语义裁决**：消息用气泡/信笺（不是铃铛）、心愿用书签/星（冻结预览是心形，可二选一并写入表）、设置用齿轮/滑杆二选一；补充 selected/pressed 视觉与角标规格；保持 20/1.7 网格。
8. **字号角色与字体**：正文 14、辅助 12 保持不变；为"叙事标题"（日期/手账/日报/空态大标题）引入系统衬线回退（`Songti SC`/`Noto Serif CJK SC`/`ui-serif`），控件仍用宿主 sans；正文继续读 `--dsw-font-family`，标题不再硬编码。
9. **无障碍与状态**：canvas focus ring；popover role/焦点返回；`aria-modal`/`aria-live`；tabs roving tabindex；空态/加载态统一容器；insufficient 只保留解释+调整+关闭。

### 6.2 工作线 B：场景光照与美术统一（P0–P1，M）

1. **重做暮色**：从"全局冷灰乘算"改为"保留暖底的局部光"——背景乘算强度降到约 0.6 或改用暖色叠加，角色保持暖肤/暖白，增加 2–3 个暖光池（窗、门、灯笼），灯笼/窗做发光 sprite；地面阴影改右下向。目标：暮色仍然暖，与暖纸 UI 不再断崖。同步拍照输出。
2. **可见家具插画化**：长椅、书架、纸灯笼优先从矢量改透明 PNG（含 back/front 分片），风铃/盆栽随后；保留矢量 fallback。目标是让"新家具"达到书桌/餐桌的绘画品质。
3. **角色与地面分离**：加强并偏移接触影；给 gpt/kimi 等白发角色加一线冷轮廓；中央地面叠极淡明度压暗/草影贴图，避免白发在阳光下"消失"。
4. **氛围延展升级**：不要再"把背景中段压扁模糊"；从真实边缘取色生成或使用一张手绘失焦花园横条；暗色主题下延展带略降亮度，减少灯箱感。
5. **可选：主题与环境联动（C 路线开关）**：新增"深色主题默认进入暮色灯火"的设置（默认关或首次建议），并保持"环境不影响主题"的独立选项；这是解决"暗色=墨绿框亮画"最直接的产品级方案，但需要重新裁决 D06。

### 6.3 工作线 C：布局密度与窄卡（P1，M）

1. **居民页密度分级**：半开抽屉首屏只保留"在场 + 选中居民 + 单一 CTA（查看日常互动）"；8 个动作移入深开/二级；"共同经历"默认折叠。对齐冻结预览的呼吸感。
2. **抽屉构图**：半开抽屉高度系数（0.48H）或抽屉起点需要重新标定，避免横切角色；可选方案：抽屉展开时默认镜头轻微上移/缩放，或半开降到 0.40–0.44H 并配"上滑展开"把手；验收标准是 340/580 半开时主角至少完整可见上半身与手部。
3. **短高方案**：H<480 时抽屉全开保留顶部 84–120px 世界"呼吸带"（或 65% sheet + 拖拽把手），内容底部加渐隐；实现 shortGutter=8、按钮 44 不缩；resize 跨 480 时重算 snap。
4. **窄宽英文**：补 `overflow-wrap:anywhere`、按钮最小宽度与两行策略、英文 320/340 截图；为"保存布置/拍摄照片/退出拍照"等长标签定义短标签。
5. **宽屏构图**：inspector 打开时可选"聚焦可见区"（世界向左平移半面板宽）或保持现状；1280 以上再放宽 inspector 到 400（需契约变更）；Dock 与 inspector 的圆角/阴影与 Git 面板对齐。
6. **滚动与边界**：为 Dock/托盘上缘增加下缘渐隐（如 24px 渐变遮罩或背景渐变），补"可感知滚动"；提高 line/soft 与 solid 的对比或给 HUD/Dock 加一层极轻投影，解决浅色边界"消失"。
7. **布局状态修复**：article/nav 层叠、toast 12px 偏差、insufficient 与 error 叠卡、loading 容器；七人页把"全员入住/仅留当前"移出网格成组；图标语义表裁决"展开小院/深展开"撞车。
8. **把清单变成回归**：为上述缺陷建立截图断言（几何/边界/对比），避免下次改版回退。

### 6.4 工作线 D：内容页面的绘本编辑感（P1–P2，S–M）

1. **心愿卡**：印章式完成态、未解锁剪影、对应装饰图标、每组一主操作；避免字符 ○/✓。
2. **手账**：时间轴 + 纸签/贴纸；左描边改为纸带；空态用现有素材合成小插画（如角色 + 便签），零新绘画。
3. **相册**：2 列（宽屏 3 列）拍立得卡——白边、日期角标、纸张阴影、点击预览；先修缩略图异步显示，再谈装饰；保留 20 张/40MiB。
4. **照片/明信片品牌层**：加"AI 小院"小署名、更精致的日期排版、2 种纸边；默认 1× 720×960（4MiB 配额），可选 2× 但必须做字节守卫；保持"三种宿主宽度构图一致"的既有验收。
5. **消息中心**：条目加头像/事件图标；"全部已读"降为次要操作；未读用角标/纸签；新消息时铃铛/气泡轻微强调一次（140ms）。
6. **设置**：本地化 `user/committed/r2`；分组标题用叙事化短句（"小院怎么亮着""怎么玩"）；主操作"完成"用 primary；补成功/未确认的纸质回执。

### 6.5 明确不做

- 全屏毛玻璃/大范围实时模糊、全屏 bloom/景深/后期滤镜（性能与照片一致性）。
- 重画七位角色或改骨架；3D/物理；自由镜头/第二场景（0.6.2 冻结范围外）。
- 用天气粒子、烟花粒子去补氛围（当前美术方向应先把光照与家具画法统一）。
- 暗色模式把整个场景压成夜景（除非采纳 6.2.5 的联动决策）。
- 外链字体/图标库、emoji 作为系统按钮。
- 为"视觉丰富"而增加常驻信息块（会破坏低刺激定位）。

### 6.7 验收清单（视觉冻结若要成立）

- **断点矩阵**：320×360、340×480、340×720、560×720、580×720、900×760、1080×760 × light/dark × zh/en，共 28 组关键截图；其中补 320/340 英文、560/900 边界；另按规范补 800×600 与宿主 800×440。

## 7. 一句话结论

**UI-v1 已经把小院从"带画布的表单面板"变成了"沉浸式绘本视口"，方向正确、底子很好；下一版不该再换壳，而应把视觉语言命名并规则化（状态/动效/主次/字体）、把场景的光与画法统一（暮色重做、家具插画化）、把窄卡信息密度与宿主主题适配补齐。** 完成这三件事，小院才会从"一张漂亮的设计稿"变成"一个长期可扩展、越看越有味道的产品界面"。

## 地图与旅行

`core/community-map.ts` 统一维护五个稳定展示 ID、双语名称/描述、图标、归一化地图点、连接、资源资格与场景契约。worldId 完全保持。现有两个场景开放；茶会广场、湖畔花园、AI 工坊仅有规划介绍，没有可运行场景引用。

HUD 地图按钮在 340px 浮卡也直接可见，不增加第五个底部 Tab。窄窗使用概览与可访问地点列表，宽窗显示带名称的地图节点。选择只更新 React 展示状态；点击“前往”才调用现有 `VillageRuntime.switchRegion`。返回/Escape 走既有导航栈，场景输入仍由父层和 iframe 双重拦截。地图本身无定时器、模型调用、存档请求或区域模拟。

初版使用明确标注的导航示意并完成独立验收。随后用户在本轮明确批准地图候选继续集成，正式包现使用**已批准的六层绘本地图**。原图忠实缩放后为1,815,775字节、估算RGBA3,080,192字节；仅在地图面板打开时校验、解码并创建Blob URL，关闭/卸载取消在途操作并撤销全部URL。六图不进入角色images或iframe纹理集合。加载失败仅回退导航示意，不写世界或改变旅行语义。批准记录与源图哈希保存于assets/community-map与独立美术目录；批准不覆盖其他美术。

旅行继续使用原 `neighborhoodCommand → commitWorld → Host CAS → publishWorld → 资源准备 → 真实首帧确认` 路径。`regionTravelIssue` 解释未开放、当前地点、无连接、未知保存、保存中、连接、未就绪、拖拽、布置、拍照和活动原因。世界操作再次检查目录开通与邻接，前端 disabled 不是唯一门禁。用户暂停不阻止旅行，且暂停状态随同世界保留。所有在场居民跟随，最大七人，旧返回脚点及失败保持原存档的语义不变。

# AI 小院：首版资产计划

日期：2026-10-20。状态：拟实施，尚无新生成/批准资产。依据 [资源审计](ART_AUDIT.md) 与用户游戏交接包。

## 统一视觉基准

一名蓝发鲸尾 Q 版角色，2–2.5 头身；固定蓝长发、蓝眼、呆毛、耳鳍、白头饰、蓝白女仆服、围裙鲸鱼和完整鲸尾。以交接拼图中央下方大 Q 版与右上版本为主，采用同一视角和柔和光源。

先做一张双手稍离躯干的中性站姿透明图，单独确认头身比、发饰、鲸尾和衣裙轮廓。现有 Child 模型作为细节参考，不通过整体压缩来制造 Q 版。

工程初值：角色工作画布 1024×1024，脚底 anchor 约 `(0.5, 0.90)`；场景逻辑尺寸 360×480。它们在样板阶段可以调整，批准后固定版本。角色实际显示高度 96–128 逻辑像素，需同时检查 300–360 CSS px 宽浮卡里的可读性。

## 首批工单

| 顺序 | 交付 | 内容与验收 |
| --- | --- | --- |
| A1 | 中性站姿候选 PNG | 单一形象、完整双脚与尾巴、真实透明；附 96/128px 高缩小预览 |
| A2 | 空场景候选 | 温馨绘本小院/小屋、统一轻俯视、连通地面；预留家具位，不烘焙人物/家具/UI |
| 确认点 1 | 用户选择视觉基准 | 依据原交接要求，批准后再批量拆件；不是以代码测试替代视觉确认 |
| B1 | 约 20–30 个功能部件 | 同坐标重建、真实补绘、接缝有余量、parent/pivot/offset/z-order 完整 |
| B2 | 四种脸 | 中性、开心、被抓起、困倦；切换不移动脸型、眼距和头饰 |
| B3 | 待机/行走/拖动预览 | 独立腿脚迈步、头发尾巴跟随；小尺寸检查关节与边缘 |
| 确认点 2 | 动作样板 | 校准动作幅度、步速和抓取手感后，再扩展地点动作 |
| C1 | 家具与道具 | 工作桌、米饭桌、坐垫、饭碗、笔记本/笔；桌子分前/后遮挡 |
| C2 | 工作/吃饭/坐姿补充 | 新手型与完整坐姿或下半身替换；不能用站姿旋转充当休息 |
| 确认点 3 | 实际场景合成 | 地面、桌前、坐垫上的轮廓、落点、视角与遮挡成立 |

部件数量由动作决定。优先拆后发、前发、侧发、呆毛、脸底与表情、躯干、裙摆、左右臂手、左右腿脚、尾根/尾鳍；不独立运动的刺绣与高光随主体合并。

工作可采用看笔记本和轻写字；吃饭至少有手/碗与嘴部配合；休息使用实际坐姿。道具、Zzz 和表情仅作为辅助表现。

## 数据契约

建议游戏资产限定为自有固定包，首版不提供任意路径导入。

- `character.json`：角色定义版本、共享画布、脚底 anchor、部件 ID、层级、局部枢轴、裁切 offset、z-order、镜像策略、姿态覆盖。
- `animations.json`：动作 ID、duration、loop、部件轨道、关键帧、表情与姿态切换、过渡时长。业务状态决定动作，动画播放结束不能自行写存档。
- `scene.json`：逻辑尺寸、出生/回退点、可走区域、简单导航点、家具占地、遮挡层、三个热点及各自 standing/sitting anchor。
- `manifest.json`：文件路径、字节数、哈希、实际尺寸、来源 ID、支持动作、批准状态。构建拒绝缺失引用和未批准的发行资产。

角色位置始终指脚底。坐姿使用单独 sitting anchor；不能把坐姿图片中心当脚底。镜像须逐部件审查，不能把单边蝴蝶结或标记无条件左右翻转。

## 制作目录与验收

拟放在 `packages/ai-village` 内：

```text
art/
  reference/       必需的参考及来源记录，不整库复制
  candidates/      候选
  approved/        批准基准
  work/            补绘与配准中间件
  prompts/         真实制作提示词与编辑链
  QA/              透明底、重建、小尺寸与动作证据
assets/
  characters/bluewhale/{parts,poses,character.json,animations.json}
  scenes/studio_01/{background.png,furniture,scene.json}
  manifest.json
```

只将批准后的 runtime 资产打包；源参考、PSD、制作历史、候选图和生成工具不进入安装包。大体积工作文件的 Git/LFS 策略在首次导入前按实际体积决定。

每批资源须经过 PNG alpha 黑/灰/白底检查、部件重建、最大动作范围接缝检查、96/128px 显示检查。图像工具失败时明确记录缺口；灰盒可以验证逻辑，但不能冒充美术完成。

## 已完成的功能

### 世界、茶会和首次奖励

- 七位居民继续共享同一世界，可选择、加入、移出、拖动，保留工作、吃饭、休息和自主行为。
- 心愿页选择两名在场居民及茶点或米饭，预留左右两席，在候选世界上同时核验席位与路线。确认保存成功后开始邀请。
- 使用有界可视图绕开家具和其他居民，依序入座，其他居民等待。路径最多 9 点，速度保持 17 世界单位/秒；不瞬移、不缩小角色碰撞范围。
- 两人实际到齐后交流 150 tick（5 秒模拟时间）。抵达期限 1080 tick（36 秒模拟时间），途中允许重规划，超过期限取消。无路线或座位被占时明确拒绝邀请，可先移动挡路居民。
- 拖动暂挂事件；取消拖动、无效落点或放回自己的预留座位会保留事件；有效离席或移出参与者解除双方预留。暂停、隐藏、关闭和离线均不推进事件。
- 完成、首篇手账、心愿标记、发现和风铃解锁写入同一候选快照。收到匹配的提交确认后才显示永久奖励；回执不确定时读回核对，不自动重发写入。
- 七位居民具有中英文茶点、米饭、熟悉后交流及风铃反应文案。界面日期从世界 tick 推导，不消费模拟随机数。

### 手账与布置

- 当前内容目录只有一篇首次相聚手账，保存第一次的参与者、食物、日期 tick 和事件 ID。重复相聚只累计次数，不覆盖首次事实，也不再发第二枚风铃。
- 风铃支持窗边、门口、墙边三个槽位及收起；预览是临时草稿，可取消或按 Esc 回退，确认保存后才发布布局。
- 布局版本参与校验。未解锁不能摆放；修改界面设置或切换页面不会改变奖励和布局。

### 正式界面与渲染

- 居民、心愿、布置、手账四页，浮卡与展开模式共享同一 runtime owner 和 iframe；切换页面、模式、语言和主题不会重新创建世界。
- 支持中文/英文、浅色/深色/跟随系统、减少动态、对话气泡开关。设置使用独立 Preferences schema 1 存储及 CAS，对账和恢复与世界明确区分。
- 340×620、340×440 浮卡及 800×600 展开布局通过检查。空间不足时提供明确展开或暂停状态；保留 sidebar、主面板和 Live2D 让位规则，以及 Git 共存布局。
- 页签支持方向键，Esc 取消布置草稿、关闭设置或收起展开。主聊天输入、焦点和草稿在交互回归中保留。
- frame protocol 2 增加视口代次和舞台投影，拒绝旧代次指针，继续校验 token、source、origin 和单调 sequence。气泡在 frame 内使用同一投影，最多两条，详情保留完整文本。
- 模拟使用父端 30Hz 固定 tick；React 常态刷新约 2Hz；Pixi 独立 ticker 停止。关闭时移除 iframe 并暂停世界。

### 存档与迁移

- 正式 Host 使用 schema 4 codec，对未知字段、版本、目录 ID、重复奖励、角色数量和完整封装大小进行运行时校验；world 上限 48KiB，完整封装上限 64KiB。
- schema 1/2/3 使用冻结的 scene 1 解码后纯迁移到 scene 2。保留身份、tick、随机数、暂停状态及可保留的活动进度；旧单席吃饭意图映射到左席，变化路线确定性重规划。
- 首次新保存保护旧 current 指针及原始快照字节。升级保护引用不计入最近 32 份普通快照窗口，经过 40 次以上新保存仍能读取旧字节；未知文件不被推测删除。
- current/previous、恢复、保存前置读取及清理共用历史版本解码。保留原有持久写入、CAS、profile 身份、owner 租约、Host epoch 和 operationId 约束。
- 世界和设置的写入与 owner acquire/release 串行协调；断连、重连和卸载等待在途任务，不让过时响应发布新状态。

## 性能结果与覆盖边界

Chromium headless + SwiftShader 的七人同场 5.104 秒样本为约 **22.14 FPS**，父页面 RAF 约 **59.01Hz**；平均绘制提交耗时 **1.42ms**，最大 **64.9ms**（包含初始化阶段）。这是 JavaScript 绘制提交测量，不等同于 GPU 完成时间，也不宣称始终达到 30 FPS。

浏览器 DPR 1、1.25、1.5、2 模拟均通过，使用固定 2 倍 backing store；并非切换实际 Windows 系统缩放。关闭后世界逐字段不变且 iframe 消失。详见[性能数据](../../packages/ai-village/art/QA/v04/performance.json)和[资源预算](../../packages/ai-village/art/QA/v04/resource-budget.json)。

本次工具运行环境中的原生 Desktop RAF 约 1Hz，加入测试专用后台节流参数并尝试前台恢复后仍未改变；因此原生 Desktop 只作为安装、实际玩法和冷恢复证据，不作为正常前台性能基线。实际交流截图成功，但暂停后的手账与冷恢复截图超时，已如实写入两份 Desktop 验证 JSON 的 `screenshotIssues`，没有用浏览器截图冒充原生截图。

未覆盖真实断电、不同 GPU/机器长期运行、真实 Windows 多档系统缩放和跨 DSH 版本。未加入提案中不属于本次内容闭环的多场景、模型调用、拍照、音频或更多心愿。当前版本保留明确的座位/路线失败反馈；不会自动搬走占位居民。

## 复现入口

在本仓库根目录、固定官方依赖和本机 Chromium 已准备好后：

```powershell
node scripts/ai-village-phase4.mjs check
node scripts/ai-village-v04-performance.mjs
node scripts/typecheck.mjs
node scripts/build.mjs --exclude-sandbox
node scripts/pack.mjs --only=ai-village
node scripts/smoke-packed.mjs --exclude-sandbox
node scripts/offline-install-check.mjs --exclude-sandbox
```

隔离 Desktop 使用 `scripts/ai-village-v04-desktop-launch.ps1` 启动，`scripts/ai-village-v04-desktop.mjs` 的 `install`、`check`、`restored` 模式执行安装、玩法、重启比对；冷恢复前以 `-Restart` 重启同一专用载体。`finish` 仅供玩法已完成后补齐状态检查，不替代首次完整 `check`。脚本核验载体路径和独立 user-data 后才停止测试进程。

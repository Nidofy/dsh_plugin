## 布局与视觉

Git 不再与 Live2D 互相关闭。小院与 Live2D 仍互斥，Git 位于当前伙伴上方。两个独立插件按同一组 DOM 标记测量布局；监听 Git 内容的实际高度变化，大屏下不再固定限制为 240px。内容超过分配空间才滚动，伙伴卡片使用剩余高度，只有一份主对话留白。侧栏展开或窗口过窄仍隐藏浮卡。

小院保留原始高清 PNG；场景背景源图为 1086×1448。100% 缩放下至少 2 倍采样，高 DPI 最多 3 倍，并限制大型画布的像素预算；开启 autoDensity，使 CSS 尺寸和绘制尺寸一致。未对原图做有损放大或重新生成。

## 桌宠与皮肤设置

「设置 → 桌宠」直接提供总开关、实例、形象、大小、互动、气泡及资源管理，无需再打开“管理桌宠”弹窗或第二个设置页面。总开关打开会恢复至少一个可见实例；关闭会卸载界面实例并停止 Host 会话观察。保存仍使用修订检查；失败回读而不重复提交；连接切换不会发布旧请求结果。

后续 0.2.1 已取消主窗口内桌宠，提供独立透明窗口载体；未适配的官方客户端显示能力提示。仅安装 tgz 无法增加原生窗口权限。载体和小院竖向铺满修复见同目录 native-pets-tall-village-2026-10-21.md。

「设置 → 鲸屿皮肤」使用官方设置插槽、Switch / Button 与 theme.overrideTokens。支持随官方浅深色切换、背景浓度、装饰开关、恢复官方外观；关闭/卸载撤销全部覆盖。客户端本地偏好支持重启保留和同源窗口同步。素材来自用户指定 dsh-deep-whale 的固定提交，完整署名与 CC BY-NC-SA 4.0 许可随包附带；不要与另一套全局皮肤同时启用。

## Runtime Adapter 权限问题：尚未复现

用户报告：官方「插件 → 导入本地安装包」提示“没有写入权限、无法安装，退出码 1”。官方将 EPERM / EACCES 等不同原因归为同一个权限提示，仅凭这句提示无法确定失败路径。

已检查本地 tgz 不含符号链接。已在非管理员 Windows 进程中，通过官方 0.2.1-rc.2 的 runProfilePnpm（插件导入使用的同一安装服务），在空缓存、离线、无生命周期脚本环境依次安装桌宠、Runtime Adapter、Notebook；第二次安装时保持 Koffi 已加载，验证通过。因此没有删除文件锁、写保护或替换可靠持久化实现来绕过未知错误。

补充日志已定位到 `dsh-runtime-adapter_tmp_<pid>_<n>/node_modules` 的 importPackage 阶段；同时有 Notebook 与 Runtime Adapter 的旧 `_tmp_` 目录被移到 `.ignored` 的记录。用户确认是首次安装 Runtime Adapter。日志证明有失败残留，但不足以判定是 ACL、目录占用或安装器版本差异，不能仅据此要求管理员权限。

用户进一步确认 profile 记录为 `pnpm@11.28.5`，与本地相同。已使用 Desktop 内嵌 Node 24.21.0 + pnpm 11.28.5 补测同版本但内容不同的包重新导入、模拟失败后缺失 package.json 的部分目录、Notebook / Runtime Adapter 两份临时目录残留，均通过；测试也覆盖已加载原生模块与目录观察器。本地仍无法复现，不能据此宣称现场权限问题已修复。诊断脚本现同时读取父目录和包内 node_modules 的 ACL、链接类型，以及可见进程加载的 profile 内原生模块路径；不读取进程命令行，不更改权限，不删除安装目录。模块列表为空也不能证明不存在其他文件或目录占用。

已增加实际升级回归：修改测试包版本和标记文件，验证安装后内容确实替换，避免“Already up to date”假通过；覆盖 auto/copy 导入方式、保持原生模块已加载，以及先 Notebook 后 Runtime Adapter 的首次安装顺序。pnpm 11.28.5 和 12.14.0 均通过非管理员离线测试，尚未复现用户机器的问题。所有测试使用临时 profile，没有修改真实 DSH 数据或全局 pnpm。

内网机器下一步需要提供安装器版本与目录状态。附带只读脚本会从 `.modules.yaml` 和安装日志读取版本，并列出相关残留目录：

```powershell
powershell -NoProfile -File .\diagnose-plugin-install.ps1 -ProfilePath "$env:USERPROFILE\.dsh\profiles\desktop"
```

如果系统禁止运行 PowerShell 脚本，不需要修改执行策略。先在 PowerShell 直接执行以下只读命令，返回 profile 记录的 pnpm 版本：

```powershell
Get-Content "$env:USERPROFILE\.dsh\profiles\desktop\node_modules\.modules.yaml" | Select-String 'packageManager'
```

profile 目录包含 package.json，官方安装日志位于其 .plugin-manager/logs/operation-*/pnpm.log。脚本不调整 ACL、不清缓存、不安装、不写设置。若路径属于正在运行的原生模块，应先完整退出 DSH 再判断；若属于受限 profile 或缓存，需要根据实际路径处理。当前未认定该远程环境的问题已修复。
